# 质量与证据

规则分四类：参考观察不等于要求；required 必须满足；target 是制作预算；exception 必须有适用原因与精确证据。页面专项补充共同业务与可读性，不统一皮肤。

全页面共同执行[视觉完成度方法](../knowledge/imported/skills/site-design/references/visual-completion.md)：清除无效空洞、保留有效留白，以购物任务组织整页构图、空间节奏、字体与色彩。合理精细的成熟版式允许成立，各站仍须有连贯的品牌辨识度。该方法在作者plan/make/check和审核者review显式加载；保留reference-rebuild目标及preserve授权边界。

图文对齐与光学平衡是长期必查项：区分结构边线、元素盒中心和文字基线，检查图片可见主体与声明的完整文字组，PC/手机及长标题变化后分别判断。page-composition-and-rhythm的observations必须包含alignmentAndBalance；只有外框测量而没有实际像素观察不能完成该项。方法及来源见上述视觉完成度专项。

## 后续任务默认执行的设计标准

本节是用户确认的长期生成与审核要求，适用于后续任务，不随本次八站交付或会话结束而失效。首页、优惠券详情、商家详情及其他含卡片页面均采用这些设计方法；尚未整理的页面专项继续如实标记缺口。new-design、reuse 及 preserve 的授权修改范围执行，reference-rebuild 同时服从明确参考的风格与布局约定。每个新任务从当前包选择并冻结规则；历史冻结产物保持原版本。

- **先确定用途再设计卡片。** 同站同用途统一规格与文字容量，不同模块按各自任务组织信息；跨站分别设计构图、外框、信息分组与操作归属。保持品牌一致性，同时保留各模块的辨识度。
- **突出真实重点。** 优惠、品牌、日期／数量分层；白或极浅卡底保持对比度。数量与日期也要按本站风格设计，可用数字、票签、印章等处理，具体造型由任务决定。主题／分类可采用目录序号或有依据的推荐表达，保留原有真实数据及入口。
- **紧凑而有容量。** 普通卡按用途和断点声明固定高度、最大宽度与文字槽；合法省略保留完整内容入口。优惠详情主券完整。商家Logo至少70×70，既定字号和操作热区不缩小；卡内、卡间、模块标题及模块之间的累计间距都要实看。
- **PC和手机分别编排。** 按实际文字和图像宽度调整列数、分组与动作位置；两端均检查主侧区域关系、连续卡片和末行。同宽跨站对照同时用于手机，不能依靠PC差异推定手机合格。
- **跨站对照逐模块进行。** 分类／主题导航、侧栏商家、普通券列表各自需要构图证据；主券有特色不能代替分类的差异检查。共享标记＋名称＋箭头后仅换色，或把所有站PC券列表默认设成双列，都需回到用途、空间和品牌重新判断。详情侧栏商家按页面规则省去可见券数与对应空轨道。
- **每次都复查容易复发的细节。** 包裹层、级联、字体加载及客户端重绘后，文字省略号、数量单位、标题、标签、图标与按钮仍须正确。看真实字形间的碰撞和空白，不仅看外框或CSS数值。
- **详情页逐模块有操作反馈。** 主券／身份卡、普通券、主区域商家、分类与侧栏商家分别设计和实测悬浮动画；结合各站卡片语言，不把全部站点套成同一动效。动画不改变布局、Logo下限、热区或相邻位置；手机按下、键盘焦点和减少动态设置共同覆盖。具体边界由详情布局方法维护。

生成者主动完成这些决定与自检，独立审核按同一标准检查全部目标工程。缺少适用证据或发现视觉缺陷时继续返工；历史通过只作为方法和证据来源，新产物分别审核。用户不需要再次提醒才启用这些要求。

具体页面边界与处理方法沿用[首页参考方法](../knowledge/imported/skills/site-design/references/home-card-reference-methods.md)、[卡片密度与构图](../knowledge/imported/skills/site-design/references/card-density-and-diversity.md)、[详情布局方法](../knowledge/imported/skills/coupon-detail-generation/references/detail-layout-methods.md)。这些是可自由转化的方法与检查标准，成品截图用于复核，不作为后续站点固定轮换的模板。

检查真实内容、图像本体、文字层级、卡片空间、四层累计间距、手机重组、同排对应文字和动作、客户端重绘、空/长/过期/无码状态。详情先核对首券全文、普通卡固定容量及主侧区域顺序，逐卡查异常空行、实际图片1:1、按钮及内部箭头、前后元素真实边界与断点±1；不得只读 CSS gap 或根部横滚。首页用自己的模块/密度标准，不能照搬详情高度。

容量按最终计算样式和实际边界核对：旧断点的 `min-height`、遗留 Grid 行列、Flex 收缩及选择器优先级都可能覆盖新规格。检查按钮到底边的内距、文字与操作是否相交，不能仅以卡片外框未溢出判为通过。具体方法由首页参考处理方法维护，各执行器采用同一条规则。

每个检查项记录页面/URL/候选、视口、状态、检查动作、截图或实际输出、结论；预期数据来自冻结快照，不能从待测DOM反推。没有样本为 not-applicable 并说明，没有执行为 not-run，不能以空集合通过。

首页及授权卡片维护按实际模块/家族分别执行 `card-density-and-composition`，PC、手机、320px 各有独立项；整页构图项继续检查模块之间关系。任务的 `sampleCases` 使用真实实体 ID 标明 short、long、last-row；单一实体承担全部角色须说明实际原因。每项填写用途与层级、短长容量、空间和操作归属、整组及末行、手机构图五项观察，并以 `observedSamples` 和 `evidenceViews` 对账 group/short/long/last-row 像素；可读整组图可复用，不能借特色卡代替普通券或季节券。尺寸/无溢出/等高结果不替代这些项。

独立 inventory 核对实际模块、`cardFamily`、真实样本 ID 及额外 `markedRoles`；原始采集器不从作者计划复制卡型作为观察。额外季节、指南或同模块子家族应补入冻结任务，或按 preserve 授权边界明确排除；不能静默忽略。原生 Harness 新任务把同一模块清单写入源码 `docs/visual-modules.json` 随候选冻结，作者交接与审核 collect/close 执行相同模块义务；历史无此契约的冻结构建不追改。封评检查证据完整性，不签发审美结论。

## 全部目标工程的必查维度

展开宿主容量必须逐站覆盖首页、真实CID优惠详情与SID商家页：外层侧栏变整行后，内层商家/分类网格按实际内宽重新计算列数。1090及宿主换列断点两侧测packing、真实卡边间距和末行；不能仅看CSS gap或根部无溢出。窄侧栏、手机、已正确圆卡和特殊推广轨道各有保留证据。新绑定在1090/1440必须映射packing.gapRange，规则通过入口和原生检查执行，不能只写经验文档。

这是每个工程都要处理的覆盖清单，不是任选几项的建议。维护只检查授权区域和实际受影响回归，范围之外明确列出；没有相应角色可写有依据的 not-applicable。首页同时检查四张参考处理方法的实际转化、每家族的宽高边界和文字容量、摘要信息是否可理解及全文详情可达。不能用照抄参考或更换皮肤证明设计成立。适用项缺证据就是 not-run，发现失败就是 fail，不能以构图不同、尺寸合格、平均分或其他工程通过来抵消。

### Logo 不能用热区或空框代替

44px 是适用操作热区要求，不是 Logo 的视觉尺寸标准；同组等框也不证明标志显示得足够大。制作前对每个角色/断点声明图片及框尺寸预算；有明确硬数值按原条款执行，参考尺寸仍标为 target。用户2026-10-20明确确认：所有商家Logo实际展示区在PC和手机均至少70×70 CSS px。最大尺寸按模块预算，不能放大后挤散文字和按钮；此前88–112px等仅是试排参考，不作为所有卡片的固定规格。

实看图形、长字标和内部留白大的商家；记录最终显示尺寸和卡内占位。框够大但标志仍缩成小字角标、或空框把标题/按钮推散，照样 fail。通过调整卡片分组和空间分配修复，不靠缩字或把长标题塞成文字柱。素材自身必要留白可保留，CSS 不额外挤出空框。若另有素材质量专项，再单独审核源图；本轮不因分辨率或锐度否决排版。

用户已否决 Paloma 手机48px身份角标和对应上下分组，旧内部通过不能作为视觉认可。此负例要求同时检查 Logo 本体与整卡构图，不能只把48改大而不看标题、日期、按钮和连续列表。每次修复说明本次选择及实测结果，不将单站尺寸选择推广为所有页面固定皮肤。

### 覆盖和证据如何记

使用 templates/coverage.json 先定义预期，再在 templates/review.json 同 ID 回填结论。每项写工程/候选、页面/组件/卡型、视口、状态、规则来源、实际样本、动作与证据；portable review 的项状态为 pass、fail、not-run 或有理由的 not-applicable，阻塞写 not-run 并补 blockedBy/reason；Harness 原生 coverage 另有 blocked 时按其 schema。不能为了填模板篡改真实状态。精确 build/hash 变化后重新检查受影响项；不变工程可引用本候选已有有效记录并说明。

新增三类视觉维度分别是page-composition-and-rhythm、palette-and-color-states、imagery-and-brand-coherence。version 2按代表路由生成1440px与393px的独立视觉项；其他宽度、断点和状态沿用完整覆盖，不能由两张代表截图推定。执行项必须填写冻结criteria对应的observations，并以pixelEvidence引用同项evidence里的实际PNG/JPEG/WebP。相同页面截图可支持多个维度；几何JSON和作者解释不能替代像素。封评程序只验证声明、文件格式与绑定，不认证截图来源、观察真伪或审美判断。

批量交付必须能逐行回答：每个目标工程检查了哪些卡型、每项用什么证据、尚有什么失败或未执行。已执行覆盖与预期覆盖逐项对账，不能用“所有页面都检查过”代替。辅助程序目前验证声明、冻结文件和证据完整性，不能自动发现人为漏列的组件或证明审美；原生门禁与独立实看共同执行，不能声称新增文字就能保证永不漏检。

严重视觉或业务失败必须返工；可读性/状态硬失败不因 minor 标签、平均分或漂亮截图豁免。离线、独立角色和工具能力缺口单列。旧六站通过是规则来源的证据，不是新页面自动通过的证据。



逐端检验构图差异：同批同用途卡在同宽手机并排，忽略颜色、圆角、阴影和按钮装饰，实际字段分组与阅读顺序仍须有意义地区分。PC 差异不能替手机通过；作者须主动给对照，独立审核先记录自己的像素判断再读计划。普通卡及重绘结果同构直接返工，不能用特色卡替代覆盖，也不固定轮换一组模板。

## 模块职责先于卡片差异

先说明各模块让用户完成什么、第一焦点是什么、信息量与占地是否匹配，再选择列数、卡片分组和视觉语言。优惠比较、商家发现、主题导航分别审核。禁止以颜色变化冒充设计差异，也禁止为了差异强行扭曲适用的阅读形态；禁止仅为两列齐底改变模块职责。手机长主标题需合理释放整行宽度。取证须包含完整页面、模块之间关系、同一模块短长内容和PC/手机，不能只裁单卡。Coupon详情的具体判断见 knowledge/imported/skills/coupon-detail-generation/references/detail-layout-methods.md。

## 专业改稿的模块语言检查

执行入口必须覆盖每个目标工程和每个详情模块，检查优惠／身份／日期三层信息、白或极浅卡底的对比度、手机图标或小组件页头，以及主券复制区真实构图差异。复制图标与导航箭头按行为区分。每个模块拥有适合任务的卡型，整页保留品牌一致性；可选齿孔、切角、齿轮等装饰不代替布局。长主标题须检查最终文字轨道，普通推荐固定容量、商家Logo至少70px，主券完整。对应具体方法见 knowledge/imported/skills/coupon-detail-generation/references/detail-layout-methods.md；以工程/模块/视口和实际证据逐项回填，未查不算通过。

## 2026-10-20 卡片特色返工的否决案例

用户明确否决八套详情的旧“几何通过”版本：对齐、字号和尺寸改过，不能证明卡片设计有特色。生成与审核都要单独核对主券、普通推荐、商家卡在PC和同宽手机上的阅读顺序、字段分组、图文比例及动作归属；把颜色、圆角、阴影和按钮外形忽略后，组织关系仍须合理且能辨认。该判断基于实际页面，不能仅由计划字段或构图名称放行。

这次草稿还暴露三个必要的反向检查：①继承的箭头伪元素可能与新SVG叠加，检查按钮、包装层和品牌栏的最终图层，不仅数DOM内SVG；②普通推荐的品牌侧栏不得误套首券，长主标题必须获得真实文字宽度；③70px图片和44px动作能放下，不等于手机双列可读，必须检查主要优惠、对象和门槛是否仍能被理解。若不成立，调整列数和字段关系，不靠缩字号、缩Logo或加装饰完成差异。

票根、品牌侧舱、标题先行等仅为处理方法，不固定八套轮换模板。用户已否决的产物保留历史，不沿用旧截图或内部审核当作当前视觉通过；最终构建和实际站点库入口另行绑定、复核。

## 全页面公共布局执行

所有页面在生成计划、首次组件实现和独立审核中执行 [全页面公共布局底线](../knowledge/imported/skills/site-design/references/global-layout-baseline.md)。按最终产物路由清单分别检查PC/手机；单行摘要、分类图标／名称紧凑关系、四层间距、阅读轴及稳定性进入同一测量器。预算由本站用途决定，不能以统一模板代替检查。页面专项pending不免除公共底线；几何measured不等于视觉pass。layout-stability按组件、路由、宽度与状态逐项覆盖；初始加载、短长内容、hover／focus／pressed、减少动态、重绘及滚动条变化必须有执行证据，未执行是not-run。优惠详情和商店详情共享修正同步实测，不能只验其中一类。



## 商家中轴不能由卡片合格推定

本次范围内含商家卡时，逐家族声明并实查Logo、名称、券数及操作区域的关系。上下居中卡须比较名称／券数的盒与可见文字行和Logo水平中轴；横排卡比较完整文字组与Logo垂直中轴。箭头占列不得把券数推偏，回正后仍查320px和断点邻域的文字／操作净距。Paloma26px负例及通用边界由global-layout-baseline维护，详情执行requireMerchantAlignment及merchantGroups.alignment，禁止漏映射或仅看外框通过。作者与独立审核同项取证，不以本次修复规定所有站的卡型。

详情按钮按品牌完成主复制／购物与普通导航两个层级，执行详情布局方法中的2026-10-22按钮条款。折角、票根、斜切仅裁非交互装饰层，实测伪元素非零尺寸、文字／图标净距及完整热区／焦点。PC与手机主次动作分别实看；样式和属性检查不能替代真实交互验收。用户排除的交互及独立审核明确记not-run。

手机卡片按global-layout-baseline逐优惠/文章家族执行action-flow与image-fit.balanceWith/fitMode；日期与紧凑动作同排或完整footer，横排照片与完整阅读组等高。列全changed/preserved/not-present和真实样本，实际点击、照片解码及断点往返。一个站或featured样本不能覆盖其他家族；无像素证据不得放行。

后续任务按公共布局底线2026-10-26.1执行图片完整内容、内页券行真实轴线/内距、Copy主动作及四项footer。旧的cover等高和仅首页action-flow不能覆盖这两类退回；build/freeze自动检查与独立视觉审核共同执行。
