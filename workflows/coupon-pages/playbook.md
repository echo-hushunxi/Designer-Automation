# Coupon 多页面制作

从本包 context 当前阶段返回的 read 列表取规则；进入下一阶段前重新选择stage，deferredRequired仍是必须执行的规则。先执行 core/start.md、core/workflow.md 和 core/quality.md 的完整适用覆盖。先列全部目标工程，再用页面框架列每工程实际启用页面；逐页运行 context 合并适用条款，不能只审首页/详情或只做一套。布局共享导致回归时扩大到实际调用该组件的页面、卡型和重绘入口。

core/quality.md 的长期设计标准随每次任务启用：将卡型、层级、四层间距、跨端重排和站点差异落实到实际方案，再按同一规则审核。上一轮站点截图可帮助理解处理方法，新站仍按自己的用途与品牌设计；不要等用户再次指出同类问题。

详情是已细化模块：主券与推荐券作用域分开、PC/手机重组、代码与按钮组合、完整商家、累计间距和长内容按 detail 标准执行。店铺页共享券行规则，但有自己的介绍/筛选/列表职责。首页先调用已有方向规则；专项实测缺口必须显式列出，新增时单独取证。

参考重建还读 knowledge/imported/skills/site-reference-rebuild/SKILL.md，采用目标参考而非原创差异指标；维护保留当前品牌，不重新生成首页。homepage-first 只在明确选定且 new-design 时启用。

涉及真实 API 时按 site-data 文档及实际响应取证，缺数据不回退虚构记录。工具组由 systems 适配；不要求另一个 Agent 装上 Harness 才能读知识，也不能把不具备的原生门禁伪装为已执行。
