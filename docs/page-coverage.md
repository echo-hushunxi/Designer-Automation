# 距离完整 Coupon 站的实际覆盖

17类是业务用途数，不是已验收的页面数。页面实例由真实记录生成；404是系统状态，不新增为第18类。机器状态以knowledge/index.json为准，node bin/da.mjs pages同时输出职责清单。

| 页面 | 内容生成依据 | 生成/审核细节现状 | 还缺什么 |
| --- | --- | --- | --- |
| 优惠券详情 | 主券、推荐券、主推荐商家、分类和侧栏商家 | active：层级、容量、完整首券、复制/跳转、状态、PC/手机、可执行几何 | 每个新候选仍需实际样本、交互和独立视觉审核；active不是零缺陷保证 |
| 首页 | 导航、购物Campaign、精选/更多券、商家和主题入口、页脚；有真实数据才加节日/指南 | partial：四参考方法、卡型容量、Logo/字号/热区、Banner上限、跨端构图已启用 | 全模块空间预算、不同首屏组织与完整交互/长短空态样本的独立覆盖 |
| 商店详情 | 商店身份、店铺券、相关商家和分类/商家侧栏 | partial：各角色布局、首券全文、筛选后首券、商家/主题/动效已有方法 | 全页面异常数据、筛选/重绘状态与业务回归的体系化独立样本 |
| 商家目录、分类目录/详情 | 商家/分类字段、关系与有效券数 | pending专项；共同规范生效 | 目录导航、长名称、不同数量、空分类、分页/加载的实际设计与审核规则 |
| 搜索、全部优惠 | 商家优先搜索、真实类型筛选/结果 | pending专项；共同规范生效 | 查询、无匹配、清空、状态切换、计数与重绘的完整交互和跨端样本 |
| 节日目录/详情 | 真实节日和关联优惠 | pending专项；有数据才启用 | 节日切换、空/跨年内容、主视觉与券组的专项审核 |
| 指南目录/文章详情 | 真实文章及对应图片、正文和相关文章 | pending专项；文章素材共用规范生效 | 阅读宽度、正文层级、图片响应式、长内容及目录/相关文章专项 |
| About、Contact、Privacy、Terms、Disclaimer | 真实服务、联系途径、数据处理与来源边界 | pending专项；正文可读性/真实性底线生效 | 与实际服务相符的内容确认、移动阅读与可用联系交互；不可伪造主体/邮箱/表单成功 |

现状是1类专项active、2类partial、14类pending专项。不能直接换算成“完成百分之几”，因为业务生成引擎与设计验收的成熟度不同。先补首页/商店详情的剩余状态，再做商家/分类/搜索/全部优惠5类核心发现页，随后节日/文章4类和说明5类。每组以真实数据、PC/手机、独立审核证据进入active，不能靠补写文档升级状态。

全站完成还要求跨页搜索/导航/复制链路、到期与撤回数据、真实计数、空/错误态、可访问性、ZIP解压及离线表现、构建/站点库身份一致。一个三页试验只能验证该三页及执行流程，不能代替完整站点验收。布局风格不因补全页面而统一；职责和检验底线共享，视觉由每站与用途决定。
