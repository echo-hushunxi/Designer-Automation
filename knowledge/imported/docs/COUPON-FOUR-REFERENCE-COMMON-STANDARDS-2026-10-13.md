2026-10-13。参考：[Couponur](https://couponur.com/)、[Dealmerica](https://dealmerica.com/)、[Couponbon](https://couponbon.com/)、[Couponister](https://couponister.com/)。目的：依据实际页面提炼可复用的设计判断与尺寸参考，对照此前17类页面框架。审美参照不等于全部功能、内容及细节已验收。

实看首页、店铺、分类目录/详情、搜索、优惠详情、节日、文章及基础说明页。统一尺寸表来自同一浏览器页的1440×1000与375×844视口、真实DOM边界和computed styles；不是截图估算。初步探索时不同标签页的视口不一致，已从归一化表排除。375视口在本次环境有15px滚动条，内容宽度360px；间距仍为CSS像素。原始数值整理见[实测记录](../engineering/reference-studies/coupon-four-20261013.json)。CUA截图已逐张观察，记录文件保存数值与观察，不冒充Harness正式浏览器receipt。未执行广告解锁或全站验收。

## 先回答共性

此前17类用途只约束业务范围，仍缺少对**配色角色、卡片比例、空间层级、购物信息密度与响应式组织**的校准。四站的可取共性是：促销区负责吸引注意，常规购物区负责连续比较；同站的文字、表面、装饰和操作形成联系，不同用途的卡片采用不同密度和构图。

| 共性 | 实际表现 | 后续生成应掌握的标准 |
| --- | --- | --- |
| 浅底承载购物信息，鲜明颜色承担重点 | 四站常规券区以白/浅灰表面及深色文字为主；红、橙、蓝集中用于促销与操作 | 先定义背景/表面/主文字/辅助文字/主操作/促销/状态颜色的角色，不随模块临时加颜色 |
| 同站设计语言有联系 | Couponur柔和促销底与红操作；Dealmerica深蓝活动与橙红操作；Couponbon橙红票券装饰；Couponister多色活动与蓝列表操作 | Banner、卡片、按钮、图标应共享颜色关系与形状语言；不用强迫所有站一种主色或按钮 |
| 字体层级来自角色 | 三站主CSS字体为Sora，一站Capriola；券标题16–17px，栏目标题采样24–32px；字号、字重和颜色区分标题与日期 | 可以一套字体用不同角色建立层级，不为了“高级”无理由堆字体；辅助信息仍保留当前≥14px底线 |
| 店铺券卡有明确分区 | 四站桌面样本均为图标区域、优惠信息区域、独立操作区域；本次主体券卡都约820px宽 | 先分配信息与操作空间，再选券形、分隔、日期位置和按钮；常用分区可以共享，具体外观应独立 |
| 优惠优先，辅助信息后退 | 标题比日期突出；操作的位置稳定，不在每条券旁增加多段说明 | 让完整优惠条件可读，类型/日期简洁分组，不用说明文字填满卡片 |
| 卡片、卡组和栏目采用不同留白尺度 | 券卡内部留白小于卡组/栏目分隔；同场景卡组的节奏一致 | 定义内部分组、卡间、标题到卡组、栏目间四层间距，而非给全站一个gap |
| 手机重新组织操作与密度 | Couponur保留文字按钮并换位置；另外三站以箭头替代桌面按钮；首页分别使用轮播、一列或两列 | 按实际父容器宽度做变体，不只缩小桌面版；保留可读文本、明确动作和当前点击区域要求 |

这里的“同站关联”不是全站所有CTA必定同色。例如Couponister列表是蓝色操作，详情Copy仍呈橙色；这是观察到的局部差异，不能归纳成跨页面完全统一已成立。几站的路由、记录ID、商家和正文高度重合，推测存在共享业务/数据底座；它们适合校准本项目，但不是四个独立行业样本。

### 可复用的设计起点

- 常规店铺券列表的**本次样本参考区间为10–24px**；可以从12–20px起稿，再以真实标题、卡高、视觉边界和一屏浏览量调整。它不是新增硬门禁。
- 内边距主要落在10–20px；图文分隔与操作分区需要各自安排。短标题不能留下大片人为等高空白，长标题也不能被固定卡高截断。
- 栏目标题到卡组采样有16/20/24/30px，Couponbon也有56px的强调型分隔。应区分紧凑工具区域和强调促销区域，不能将大间距撒到所有模块。
- 桌面内页主券区约占内容容器七成，侧栏与两区间隔占其余空间；采样主/侧分隔约40–60px。首页可采用更宽的商业构图，内页保持连续阅读与比较。
- 日期字号11–12px、手机4.5px外边距、28–32px箭头以及部分长标题省略，是观察值。当前生成标准仍要求允许文本≥14px、手机边距12–15px、充分点击区域、完整优惠条件；这些较弱样本处理不直接采纳。
- 同一站的spacing应形成明确层级；参考数值包括10、18、20等，并不是整齐统一的8px倍数。不要宣称四站都使用同一spacing系统。

## 卡片应分用途设计

1. **首页促销表现**：Couponur是人物/购物视觉配商家板；Dealmerica是活动海报；Couponbon是商家优惠轮播；Couponister是大券与小商业块拼图。共同的是购物对象与行动明确，促销区与后续浏览区形成节奏。不能强制每站人物Banner、同款左右栏或相同数量卡片。
2. **普通券卡**：券标题、日期/状态和动作优先。四站实际点击店铺页第一张整卡均进入对应CID详情。本次记录了真实导航，未执行广告解锁后的复制字节核验。
3. **商家/推荐入口**：Logo、商家名、实际券数、店铺目的地。分类和搜索都围绕商家结果展开。四站搜索Nike均操作到`/search?q=Nike`；结果数量不同，两个样本落到no-match。未核对两站全量搜索数据，因此不宣称所有相关性通过或把差异直接判故障。
4. **促销商家卡与具体优惠卡要先定义身份**：部分首页卡显示店铺名和券数，却链接具体CID。这种字段/目的地混合不能直接复制到新站。建议结构计划明确它是商家聚合入口还是某一真实优惠，分别绑定字段和动作；可新增表现变体，不能无依据增加折扣或统计。
5. **主券**：四站均将本券作为视觉主角，之后是关联券、Similar stores与浏览侧栏。当前不少Copy入口有广告提示；本期保持已约定的显式揭示/复制和拒绝反馈，不引入广告门禁。

### 发现的额外页面

Couponbon还有可公开访问的[商品/服务榜单与对比页](https://couponbon.com/topGoodsList/meal-delivery-service.html)和[商品/服务推荐详情](https://couponbon.com/topGoodsListDetail/factor.html)。首页相关入口当前隐藏，因此不是四站共有的购物主链路。

建议作为**两类可选扩展**列入页面能力清单，不立即成为每站必做页。当前Harness接入的公共数据契约未包含独立榜单、评测评分或这些商品详情数据；启用前必须有真实内容、实体ID、排序依据及操作目的地。不能为了补页编写9.9评分或评测。

实际还观察到内容风险：餐食配送榜单里的Factor，其推荐详情文本却介绍业务流程优化工具。这是主题/实体不一致的可复现观察，需要新增实体一致性校验，不能把该文案作为正样例。

## 还缺哪些生成标准

| 应补充的标准 | 放到生成前的具体决定 | 实际验收方法 |
| --- | --- | --- |
| 色彩角色和形状语言 | 定义背景、表面、文字、主操作、促销、状态；决定哪些变化属于业务状态，哪些属于构图 | 比较首页、店铺、详情和客户端重绘后的实际颜色/形状，检查无意义漂移 |
| 四层空间节奏 | 写卡内、卡间、标题到卡组、栏目间的spacing层级及不同父容器变体 | 从真实边界量gap、margin和外伸装饰，检查一屏浏览量，不只读CSS gap |
| 卡片空间预算 | Logo、文本、动作各占多少；长标题怎样自然增高；哪个元素可以移动 | 用真实短/长/极端标题和宽Logo，在1440/768/375/320及断点两侧实看 |
| 首页促销与内页浏览分工 | 选择商业主视觉类型和后续卡组节奏；分开促销卡、普通券、商家卡 | 首两屏是否清楚可购物；内页能否连续比较，避免所有模块同一密度和同一造型 |
| 页面用途与导航准确对应 | 明确每个入口去商家、分类、优惠还是文章；目录不能只凭URL/标题命名 | 实际点击并核对目的页、CID/SID和展示字段；本次View all brands反例用于测试 |
| 数量的范围与单位 | 商家数、全库券数、当前分类券数、当前渲染结果分别绑定countKind/范围/快照 | /allCategories中的218对应Beauty的218 brands，不能随意改叫218个优惠；交叉核对集合与过滤条件 |
| 日期、时效和内容身份 | 原始发布日期、抓取时间、活动年份、截止日期分开；状态有明确派生阈值；绑定实体ID | 刷新不得把抓取日当发布日期；不机械补当前年份；已过期不领取；详情不能换成同名其他业务 |
| 可选模块与能力依赖 | 首页/侧栏表现可选，榜单/广告/评分需要能力和数据；不启用就不生成占位内容 | 检查可见DOM与能力声明，不将隐藏栏目、空广告位和未接通入口当完成 |
| 视觉完成度独立校验 | 页面用途和字段正确后，再检查比例、密度、色彩、动作和跨页一致性 | 引用当轮实际页面/像素证据；区间合格不等于优秀，不靠更多小字或强行等高修布局 |

既有业务、真实性与尺寸要求仍有效。参考站的推荐数量、字体小字、Logo裁切、广告和title截断若与当前约定冲突，记录差异；此次研究不擅自降低门槛。页面/卡片/模块既要有可执行业务契约，也要有基于真实参考的视觉计划和实际复核，才能减少后续人工返工。
