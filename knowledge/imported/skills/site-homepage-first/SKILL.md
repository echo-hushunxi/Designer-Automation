# 首页驱动创作

用户于 2026-10-14 确认的独立生成模式。Harness 与 Codex 采用同一方法。先调用 `site_harness workflow`，使用 `generationProfile="homepage-first"`；新项目用 `mode="new-design"` 和同一 generationProfile 导入独立源码。局部维护继续 preserve，不重新生成方向。

读取共用 Coupon 生成标准（`skills/coupon-generation-standard/SKILL.md`）和真实数据技能（`skills/site-data/SKILL.md`）一次；制作时按 workflow 定位，审核时按候选 context 的冻结位置定位。该模式首页以本文件和绑定的有效框架为准；其他页面保留现行业务职责、字段、尺寸、状态及真实数据标准。2026-10-15 用户补充的按钮创作、文案搭配、首页券量与 Logo 占比要求只绑定此模式的新生成；不回写历史产物，不改变其他模式。

本模式制作前读取[六站修复后的预防与复验](references/repair-prevention.md)，作者自检和独立审核使用同一 HFP01–HFP13 / HFG01–HFG03 清单。公共 workflow 的 `homepageFirst.repairPrevention` 返回原文与案例索引的路径/hash；新导入的冻结框架说明包含该清单，审核读取候选自己的冻结版本。首页方向和全站阶段按各自范围执行，不新增阶段或固定皮肤；完整案例是方法证据，不是下一站自动通过的证明。

首页卡片还须读取[四张参考的处理方法](../site-design/references/home-card-reference-methods.md)：提取信息分组、重点和空间关系，按本站用途转化；不得复刻参考或固定轮换卡型。摘要卡按家族/断点声明宽高边界、文字行数及省略，完整数据和本券详情保留；商家Logo实际图片展示区PC/手机均至少70×70。本条为用户最新确认，覆盖旧依赖的全文撑高及较小Logo建议。

## 1. 定首页方案

Banner 必须有，导航和页脚正常保留。内容池包括即将结束的优惠、推荐、精选、商家推荐、热门分类、节日/纪念日、省钱指南。板块数量自由：4–5、6–7 或其他合理组合都可以，按实际风格、内容和整页节奏决定，不要求凑齐。标题可以自由改写并使用合适的小图标、强调色或其他视觉处理。文章启用时放在首页最后或倒数第二；节日和文章依赖真实关联内容。

用现有 docs/site-structure.json 和 docs/site-craft.json 简短记录板块用途、主次、配色角色、四层间距和手机组织。直接沿用导入后 docs 中的模板键，不猜测结构；无需新表单、固定风格名、多套方案或逐步人工批准。首页券模块在原结构计划中写 cardDesign/actionDesign：前者说明卡片分区与 Logo 占比，后者说明按钮构造、板块角色及文案/类型/目的地的关系；在现有 density.home 记录初始可见券量和分配原因。它们是设计决定，不是数值合格或视觉通过的证明。

## 2. 完成视觉创作

先确定整站字体层级、颜色关系和空间节奏，再共同创作 Banner、卡片与真实操作。Banner 的媒体、构图、人物/商品场景、拼贴、促销块、轮播均自由；标题和操作保持 HTML，图像与购物用途匹配，不把优惠事实画进图片。

按本次用户确认的偏好，默认 Banner 采用鲜艳、有点击吸引力的红、橙、亮粉、明黄等颜色，避免绿色或蓝色作为主色。用明确的主体、商业构图与主操作形成视觉重点；鲜艳不等于整页铺满高饱和色，阅读区域仍需清晰、舒适，并与卡片和按钮协调。具体搭配、比例与表现方式保持自由，后续明确的用户 brief 优先。

每个板块遵循一个思路：用途 → 信息主次 → 卡片分区 → 按钮融入。先选择该组实际需要展示的字段，再安排 Logo、优惠信息、日期和操作。小卡可省略完整标题，以来源真实的简短优惠与期限 tag 建立层级；不能丢失 Up to 等会改变含义的限定或编造折扣。需要完整标题及较多信息时增大卡片或减少并列数量，不挤窄标题、缩字或把按钮硬塞右上角。大部分优惠券卡片保留清晰的真实按钮，不靠批量删按钮来制造简洁；少数用于快速浏览的简卡可用整卡及可聚焦的本券入口。以用户实际看到的标题板块为单位保持操作规则一致：该组券卡都有按钮，或该组都不附按钮，不能在同一标题下通过另分组件类名混排有按钮的大卡与无按钮的小卡。不同板块可以有不同构图和操作位置，不能随机排列。真正的限时／最后优惠板块保留优惠标题，可省略日期；不得把普通末尾板块冒充即将到期，或编造紧迫感。页面背景采用白底，卡片材质和局部品牌色按本站风格决定，不误读为全部卡片必须白色。具体用户 brief 优先。

先实看本站现有字体、主视觉、图像、形状和购物节奏，再决定适合的卡片与真实操作；不提前给批次分配六种风格、按钮菜单或固定模板。跨站不能复用同一套卡片构图和操作位置后只换颜色，也不能把同一批“大 Logo＋相同 tag＋相同日期＋相同按钮”批量铺满。差异须在真实页面的比例、信息组织、字体层级、实际操作构造与手机重组中成立；风格名称、装饰、工具生成稿及数值达标均不能证明成立。

**按钮创作**：Banner 的主操作要形成商业主视觉的明确焦点，优惠券按钮要融入卡片且有可感知的点击吸引力。结合该站的主题、图片和板块角色，决定轮廓、材质/层次、分隔、位置、文字/图标关系及 hover/focus/pressed 反馈；不能把“纯色矩形/胶囊加箭头”或空心描边作为所有站的默认答案，也不能只换颜色、加图标就宣称有特色。实色、描边、开放式文字仍可按用途使用，不强制某一种造型。Jingle 的吊牌和票根只是该站的成立方案，不成为其他站的母版；市场贴纸、柔软胶囊、机械按键等也是方法示例，不是必须选用的风格清单。小符号与主题元素可用，但不能遮挡信息或制造无依据的热度、稀缺标签。以实际视觉完成度判断，不以装饰数量判断。

**文案搭配**：领取类按钮按真实优惠使用 Get Code（必须确有优惠码）或 Get Deal（无码促销）；推荐、精选等编辑浏览区可使用 View Now。需要详情语义时仍可用 View Details，但不能全首页机械统一为它。按板块用途、优惠类型和实际点击行为选择，不按卡片序号随机轮换，也不要求每站凑齐三种文案；某组全部有码时使用 Get Code 是正确的。保持与目的地一致：券入口仍绑定自己的 CID；Get Code 进入本券掩码详情，主券显式激活才揭示/复制、刷新隐藏；Get Deal 可进入对应促销详情再前往真实商家，或走已定义的正确促销目的地；View Now 进入相应优惠内容。改文案不能把无码券伪装成有码券或擅自改变领取流程。

**首页券量**：首页要能连续浏览和比较足够多的真实优惠，不能只有几张展示卡、巨大留白，再把内容全藏到“更多”之后。根据版式、商家覆盖、长标题和整页节奏安排初始券量；本轮六站的 18–32 张可作密度起稿参考，既不是最低/最高数量，也不是每块配额，板块数仍完全自由。分页、筛选或加载更多服务于继续浏览，不替代首批内容。以真实 CID 去重、合理覆盖商家，排除过期券；数据不足时如实缩减并说明，不重复凑量或压缩字号。手机允许重排、分批浏览，仍要有实质内容且不产生失控长墙。

**Logo 占比**：商家标志应成为券卡内清楚、可识别的视觉锚点，与标题和按钮共同分配空间，不能只是很小的角标。主券卡可从桌面 88–112px、手机 80–104px 的框开始试排；这些是本轮参考值，不强制所有站、板块、横卡或长标同一尺寸。检查的是标志本体的实际辨识度与卡内占比，不能只放大空框。使用对应商家的现有官方素材；本排版专项只检查图片显示区域至少70×70及其占比，不处理源图清晰度。保留原色、原形和完整比例、contain 及现有边框要求，不裁标或伪造；白色商标配合适的深色承托面。不得为放大 Logo 挤断商家名、优惠条件或按钮，手机端重新分配空间。

同一卡片类型、同一视觉排的商家名和优惠标题必须检查实际第一行的起点与基线，日期和按钮沿该排的设计轨道对齐。用长短标题、可换行商家名相邻的整排实测；卡框等高或声明 subgrid 不能代替文字对齐。改列数、字体加载完成和客户端重绘后复查；摘要可用约定固定标题区域及行数省略；必须核对整组实际对齐、空间比例和详情可达，不能缩字或留出过大空位。未对齐属于必须修复的生成缺陷，不标成完成。不同板块继续使用各自的卡片、按钮和排列。

学习 Couponur、Dealmerica、Couponbon、Couponister 的边缘箭头、券码尾部、票券分区和大卡/列表主次关系，作为可选方法，不固定为模板。可按需要从 Refero Styles 选择一个相关 DESIGN.md 提供配色、字体、构图与组件参考，适配 Coupon 内容后给 Stitch 使用；有可用 Stitch 时生成视觉候选并结合实际源码实现。保留来源和采用的具体决定，缺少外部能力时如实记录；不依赖指定参考网站或外部工具才能使用该模式。拿不准的组件可局部比较小样，多套方案不是必经步骤。

## 3. 集中检查和打磨

完成真实首页及代表店铺/详情页后，在桌面、手机和 320px 实看，布局换列时包括平板；委派独立 site_design_review 一次集中检查 Banner、首两屏和整页节奏、卡片/按钮表现、真实内容及手机重组。同一轮中查看按钮正常/交互状态与完整文案、初始券量、Logo 展示区域尺寸和占比、同排文字/日期/操作对齐，以及筛选/加载更多后的重绘和真实领取行为。新增卡片的 Logo 路径和图片解码必须在预览及离线包中有效，不能只检查初始 HTML 的静态图片。只看加载成功、外框尺寸或计划声明不能证明图像可辨认、内容足够或按钮有吸引力。使用已有 homepage-direction 阶段和集中问题包，不增加审核层、评分表或创作审批。保留成立的方向，按问题位置和原因统一修整，复查本轮修改及其影响。计划完整、构建成功或控件造型不同都不能单独证明视觉优秀。

同一轮检查实际内容的困难情况：列表样式不能误伤详情主券，窄屏分类文字不能被 flex/grid 挤成零宽或逐字竖排；整卡空白、标题、店铺链接、CTA、键盘和文本选择的行为要各自正确，hover/focus 与点击范围相符；侧栏补充主栏的选择，不机械重复同一批商家；推荐的末行要有整体感，不能编造记录填格。Logo 核对最终显示尺寸与实际占位，保持完整比例，不裁标；本专项不追加素材分辨率或清晰度工作。放大后重新分配整卡空间，桌面店名不能被挤成碎片；320px 长标题不能被困在 Logo 旁的窄列而两侧空白，应按该站风格用完整行或其他有效重组。每个板块同时核对第一行文字、日期与操作轨道，不能只对齐按钮。脏数据中的使用人数/采集控件文案不能当优惠标题；在展示派生层隔离并记录原因，原快照保留，页面、计数和重绘共同排除。将这些观察附到已有集中问题包，未修复的主要缺陷不得报告完成；不增加流程阶段、板块配额、统一侧栏或卡片皮肤。

## 4. 延展全站

方向成立后，沿用首页的字体、配色、组件细节和按钮语言，按各内页用途调整排列与密度，完成实际启用的页面；使用现有 full-site、业务/浏览器/离线审核与 HTML ZIP 交付。一个页面用途不必重新发明一套设计。最终审核集中处理实际问题。

2026-10-15 用户追加的生成与验收要求，继续仅作用于首页驱动模式的后续生成：

- **随站附带四个信息页**：About、Contact、Privacy、Disclaimer 分别生成独立、可访问的完整页面，并在页脚提供正确入口，沿用首页的品牌语言。正文按各页职责写实，不能只有标题、占位段落或空链接；联系方式和经营信息来自真实配置，缺失时如实记录，不编造邮箱或服务承诺。原合同已有的 Terms 页面继续保留。
- **逐页生成 TDK**：首页、各详情、目录及上述信息页的实际 HTML 都包含非空的 `<title>`、`<meta name="description">`、`<meta name="keywords">`。按当前页面用途及真实商家、优惠、分类、节日、文章或站点信息生成，不能全站照搬同一套，也不能只在配置文件声明而漏掉导出 HTML。优惠有效性和验证状态不得夸大。
- **详情主内容统一1200px**：商家、优惠券、分类、节日、文章等全部详情页，以及上述四个信息页，宽屏可用空间充足时采用居中的1200px页面级主内容容器；有侧栏时，主栏、侧栏及其间距合计1200px。窄屏随可用宽度收缩并保留手机边距，不固定1200px造成横向溢出。文章可在该容器内部安排合适的正文行长。首页宽度继续自由设计，不套此限制。

全站交审时，作者和独立审核逐页核对四个信息页正文及页脚目的地、实际 HTML head 的 TDK、代表性详情在宽屏的1200px容器和手机收缩结果；离线包复查同样内容。缺页、缺 TDK 或容器不符都记入原集中问题包，不能仅凭首页或配置检查放行。

完整验收或用户指定外部 Coupon skill 时，再读取[全站覆盖与漏审预防](references/full-site-coverage.md)；候选审核定位其随构建冻结的 `design-kit/skills/site-homepage-first/references/full-site-coverage.md`，不从编译后的 docs 目录猜相对路径。以实际启用的路由族、规定宽度、关键状态和技能条款建立证据索引，并附在原集中问题包中；原生工具的最小覆盖不等于用户技能的完整覆盖。未运行、因授权延期和不适用分别记录，不计入通过。卡片设计继续由各站风格和板块职责决定。

## 保留的底线

标题与视觉自由；文章位置；现有尺寸和业务标准。券标题/商家名 16–20px、其他允许文字通常至少14px、实际操作区域至少44px、手机主内容边距12–15px，具体按共用标准。完整条件可读，官方 Logo 保持原形和比例，真实有效期与关联正确；首页动作采用上面的板块/类型语义，覆盖旧依赖中统一 View Details 的文案要求，其他业务要求不放宽。列表有码进入自己的掩码详情、主券明确激活才揭示复制，无码走正确商家目的地，过期券从购物展示中排除。不额外添加没有业务职责的装饰眉题/副标题，详情保留当前规定的页面板块。间距参考帮助起稿，配色、字体、圆角、列数、卡片比例、材质和按钮构造不设统一皮肤。
