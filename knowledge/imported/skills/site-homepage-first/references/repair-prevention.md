2026-10-15。仅用于 `generationProfile="homepage-first"` 的后续生成、该模式的全站延展和适用维护；普通生成、参考站重建及未采用该模式的历史项目不新增本清单的要求。已有业务底线仍按各自冻结合同执行。

作者构图前选择适用项，把决定放入现有 structure/craft/design 记录；交审前用真实候选操作并检查。审核者先看画面形成独立判断，再按候选冻结版本复验。将下面 ID、实际 route、width、state、证据及结论附到现有 handoff/集中问题包，不创建新的报告阶段。

完整验收及用户指定 Coupon skill 时，结合[全站覆盖与漏审预防](full-site-coverage.md)从实际启用路由和技能条款检查覆盖。该文件随构建冻结在 `design-kit/skills/site-homepage-first/references/full-site-coverage.md`；编译框架文档中的相对链接以此位置定位。原生最小覆盖、首页通过与历史交付均不代替当前全站逐项凭据。

首页方向阶段检查首页已有组件、搜索/筛选/重绘和代表卡片，记录偶然发现的其他失败；全站阶段再系统覆盖启用的店铺、列表、详情及离线状态。早期方向成立不等于全站通过，不为这张清单提前重复整套最终验收。

## 工程检查也进入同一轮

- **HFG01 绑定与结构**：新候选的 framework/craft、计划、来源和哈希应真实一致；有既存有效绑定却漏构建元数据时修正绑定，不伪造通过结果。单一主标题按实际活动DOM检查，inert template 中的备用标题不是第二个可见主标题；同时保留对真实重复标题和失效券领取控件的拒绝。不可用页面不套用有效主券的模块断言。
- **HFG02 真实执行**：自检与独立审核检查打包后的脚本实际运行、变化后的DOM和画面；HTML/ZIP链接检查无法单独发现未映射的模块导入或 hidden 与 display 冲突。记录实做的正常复制、降级/拒绝反馈及能力限制，未运行项不能补成 pass。
- **HFG03 精确产物与权限**：审核、源码、截图和下载绑定实际 build/revision/hash；修复后建立新候选，旧拒绝记录保留。并发更新先对齐当前基线，备份并检查变更范围。用户允许下载、独立局部复验、完整技术验收和用户审美确认分别记录；下载授权不生成缺失的技术凭据。工具限制如实记 not-run，不绕过浏览器安全策略，不用HTTP冒充离线通过。

全站阶段将[技能第4节的交付要求](../SKILL.md#4-延展全站)一并纳入 HFG01/HFG02：实际访问 About、Contact、Privacy、Disclaimer 并检查完整正文和页脚入口；逐页读取导出 HTML 的 Title、Description、Keywords；宽屏测量各类详情及四个信息页的页面级主内容容器为1200px（含主栏/侧栏/间距），手机核对收缩与边距，首页不套此宽度。不能用文件存在、配置有字段或 CSS 声明了 max-width 代替实际内容、head 和容器测量。沿用原全站与离线检查，不新增审核阶段。

## 第二轮补充：券卡组合与漏检边界

继续仅用于首页驱动创作，并入现有 HFP01/04/06/08/10/13 与集中问题包。案例见 [六站卡片修复](cases/six-site-card-refinement-20261015.json)，不新增阶段或皮肤。

- 先按板块职责选择图像、Logo、完整标题、真实期限／数量和必要操作，再排主次；不把所有字段塞进每张卡。让主要优惠与行动容易一眼找到，以局部强调建立配色层级，检查文字、图像和操作的组合。
- 2026-10-16 用户再次纠正：白底指页面背景，不能强制所有券卡白色。先实看各站自身风格，再决定其卡片及按钮，不预先分配一批固定皮肤。作者与独立审核横向看批次真实画面；同一构图、字段排列和操作只换色仍退回。不能为了测量通过把按钮挪到右上角；要检查按钮与内容的实际关系。
- 小卡可用真实的简短优惠和期限 tag 代替完整标题，减少字段，放大清晰完整的官方 Logo 本体；完整信息卡应给更大的有效阅读空间。简卡保留可聚焦的本券入口，主券仍保留完整标题和真实条件。展示派生不改原快照，保留 Up to 等限定，不编造优惠、库存或热度。审核不能为迎合旧字段清单强行塞回完整标题和重复按钮。
- 大部分优惠券卡片保留清晰的真实按钮，卡片可增大、减少并列数，为 Logo、信息重点和操作分配足够空间。实际标题板块内统一按钮有无，不能把一个 H2 下的大卡与小卡声明成不同组件来混用规则；分别查看整组和手机重组，避免随机排列、标题挤压或按钮硬塞右上角。少数整组无按钮的浏览区仍需可聚焦、正确 CID 的入口及整卡操作。真正的限时／最后优惠组保留标题，日期可省；普通末尾板块不自动等于即将到期。
- 首页首两屏之外，至少实看实际采用的第二类券区及整区收尾。单卡紧凑不证明区域紧凑，数字合格不证明留白合理；精选列不能留下没有用途的整片空洞，筛选重绘须保持同一构图。
- 短优惠 tag、期限和按钮只有少量字段时，不要机械占满整行容器；结合真实内容组织相邻卡片与阅读距离。平板还要检查内容是否堆在左侧而右边大幅空置。根据本站和字段决定重组方式，不把本次货架列数或断点规定为通用模板。
- 更换组件标记时同步静态输出、客户端重绘、过期移除和计数绑定。用稳定业务语义定位，避免统计只依赖某次视觉类名；初始、筛选、定时变化及刷新都要对实际可见记录。
- 核对首页素材本身与完整来源图，而不只检查 CSS contain；旧派生图可能已经裁掉标志边缘。动态 Logo 映射中未被初始 HTML 引用的素材也必须进入真实 ZIP，不能只按静态 src 收集。用解压的 file 页面实际筛选、加载更多并等待新增图片解码，检查完整轮廓、清晰度、光学占比及商家入口；真实原图和原始快照保留。
- 不继承未经核实的“官方／高清”标签：SVG 的画布宽度不能代表内嵌位图分辨率，小 favicon 加手写商家文字也不能冒充原标。查看文件实际路径、位图、文字及图体占比，并对照可核实的原始来源；需要更清晰的角色变体时保留原色和完整形状，诚实记录既有素材与新官网来源的区别。首次输出、搜索重绘和离线包使用同一商家映射。
- 原标换成白色或横向变体时，逐角色检查实际背衬和光学大小；首页可见不代表商家、详情、关联、侧栏或动态搜索可见。等图片解码和样式稳定后实际看像素，确认页面样式没有把白标的背衬盖回白色。小角色可用有来源的完整官方紧凑变体并保留可读商家名，不裁标、放大模糊旧图或手写替代。
- 手机实看按钮内部完整文字、长商家名与文字商标的绘制范围，不能只测按钮外框。给横向文字商标足够空间且保留可读字号；实际可用宽度还会受常驻滚动条影响，不能用根裁切掩盖溢出。
- 同站商家／券详情用首页确定的组件语言与统一的数据含义。逐页核对冻结合同中的真实推荐量和当前商家排除，不把某站16项硬要求变成首页配额；跨页结构相近仍须审实际字体、动作和密度。
- 实际解码当前视口内图片后再判断空白图或 Logo 质量。屏幕外懒加载图像不应阻塞整轮检查。矛盾记录隔离后，生成路由仍保留诚实不可用旧URL，相关计数与恢复入口同步。

案例里的280／200px、按钮宽度、某站列数和配色只说明本次实现，不规定未来站点的统一尺寸。后续候选仍由作者和独立审核执行同一清单，历史技术证据不继承为新的通过结论。

## Coupon Skill 实机验收补充

仍只用于首页驱动创作，归入原 HFP01/03/04/05/08/11/12/13 与 HFG02，不增加阶段或统一皮肤。

- 卡片按板块选择字段，但不能让泛用优惠标题依赖微小文字 Logo 才能识别商家；该板块合同要求商家名时，静态与重绘结果都保留可读的文字身份。先检查父容器内的真实可用宽度，再决定卡片横排、列数与手机重组；同排日期和 CTA 按明确轨道对齐。
- 实测输入框和提交按钮本身的点击区与边缘命中，不能把外层表单高度或隐藏 label 当成扩大后的点击区。共享 Header 保持紧凑，同时满足真实控件尺寸；拒绝复制后动态出现的手动取码输入框也按同一点击尺寸检查。
- 组件跨断点延展后，检查旧 CSS 的 display、grid-area、伪元素及继承优先级。对实际可交互链接使用可见、可聚焦的盒子；不能因 display:contents 看似对齐就漏掉键盘不可达问题。
- 键盘激活展开按钮后，焦点进入新显示内容中的合理起点，后续 Tab 不能跳过整批新增优惠。筛选操作保留在筛选控件上的焦点，避免不相关的强制跳转。
- 在真实成功、降级和拒绝复制状态下分别核对反馈文字的可读性。改变代码区底色后，同步检查成功／错误颜色；共享焦点样式也要在深色页脚实际 Tab/ShiftTab 检查，不以正文可见替代。
- 具备可用降级能力时，要核对降级复制后的实际剪贴板，不能把诚实的手动复制提示记成降级成功。有码和无码主券都须在操作激活前重新检查到期；周期清理不能替代这道检查。
- 用同一个 CID 比较全部优惠列表、商家券列表与详情推荐中的普通券，核对实际卡框和 CTA 语言。检查页面专属 CSS 是否漏掉某一族；首页板块与详情主券仍按各自角色设计，不把一致性扩张成统一跨站皮肤。
- 到期复核包括页面已打开时的主券操作、静态初始卡片、客户端重绘、首页策划区、店铺身份、推荐／侧栏、节日目录与详情。动态搜索命中与无匹配建议中的商家计数也必须绑定同一刷新；实际保持已输入查询和焦点、自然跨过来源到期时间，不能用重新搜索或刷新页面代替。移除优惠后同步更新全部有效数量和空态／恢复入口；只让主券刷新后不可领取不够。用真实到期时钟能力留证，模拟与真实时间分开说明，不修改来源期限。
- 用实际解压的 file 页面操作搜索、筛选和加载更多，再分别点击商家、优惠标题、CTA 与整卡目的地。动态创建的 href 和 data-card-href 也使用离线路由解析；静态导出时补过 index.html 不能证明重绘链接正确。
- 没有配置的邮箱、域名或广告不能编造。维护审核先明确既有配置与用户授权范围；“保留已有邮箱动作”不能扩张为必须新建邮箱服务。真实配置缺口如实说明，现有商家支持入口必须能实际到达。具体延期验收仅作用于获得该授权的当前任务。
- 测量器先辨认真实业务角色：显式空态中的“暂无优惠／不可用”状态标题不是优惠券标题。状态检测须覆盖实际采用的语义标记，隐藏提示或其他区域的提示不能豁免有效卡片；各规定宽度仍需有真实充足内容的检查。判定器有误时保留旧回执，用修正后的真实重测替换受影响的审核引用，并说明原因，不能缩小状态标题或改站点来迎合误判。

## Stitch / Refero 双站与六站再次复验的补充

继续并入 HFP03/04/08/12/13 与 HFG02/03，仅用于首页驱动创作。过程、真实失败及最终交付身份保存在 `generation/stitch-duo-20261016/`，制作经验见其中 `LESSONS.md`；最终状态只读取该目录的精确交付清单和原生报告，不能把本节当成候选通过凭据。

- 从真实宽度和内容形成同排秩序。一行／两行期限可能让优惠值、分隔线、日期首行错位，即使按钮底部已齐且测量器没有失败。实际看完整相邻记录，再决定该板块是否需要共享轨道；不把某站四轨结构变成公共模板。
- 首页商家子集通过，不证明完整商家目录或内页推荐通过。实看同一组件全部真实名称与数量，在本站实际断点两侧和320px检查文字的绘制范围、装饰箭头与卡高。先给名称／数量／箭头合理空间或重组列数，不能缩字、遮盖或夹定高度来满足尺寸。装饰箭头与真实独立按钮按各自语义审核。
- 搜索外框达标，内部输入框仍可能过小；Header 的真实项目数量、入口和实际控件以当前冻结合同为准。不能继承旧站的多余导航或把外层高度算成输入框点击高度。
- 新来源的官方 Logo 要保留可验证 URL、完整原文件、色彩、比例与必要背衬。光学大小、当前角色与懒加载解码一起看；原图完整不代表每个角色的实际画面均可辨认。分类图像／图标也保留真实来源、固定版本与许可，普通箭头不是分类内容图像。
- 有具体时刻的来源期限按原时刻失效，不延长到当天末尾。无时区的解析方式记录清楚，服务端与浏览器一致；真正只有日期的值另按其明确约定处理。真实操作激活前复核，停留自然跨期、模拟大幅跳时与刷新后的状态分别留证。
- 券被移除后继续检查它所属模块的标题、分隔和恢复入口。初始零条与运行时变零均遵守该模块已声明的空态策略，不能留孤立的“更多优惠”标题；局部推荐为空的说明也要明确其范围，避免暗示整个库无优惠。重载和反复刷新应得到同一状态且不重复插入提示。
- 真实少量内容也核对英文计数单复数、空态和分组收尾。修文案不改变真实数量、来源类型或优惠条件。简单优惠摘要仍保留 Save、Up to 等实际含义，不能为了短标签丢失限制。
- 逐页 TDK 的非空检查之外，核对浏览器标题中的优惠主体。来源通用优惠标题补真实商家名，保留正文和限制，不靠 CID 制造虚假唯一性，也不以全站强制唯一替代真实语义。
- 研究图只提供方向；将其落实到真实公共库、官方商标和实际页面。记录实际看过的公开 Refero 页面与 Stitch 生成／修改屏幕；接口未获权限时如实说明，不能冒称已提取付费内容，也不能把原型中的虚构数据直接发布。
- 为融合照片更换 Banner 底色或遮罩后，重新检查普通支持文案与大标题各自的真实背景和对比。大黑标题满足大字阈值，不证明旁边16／18px普通文字满足普通文字阈值；先确认文字下实际像素与图像透明区域，再选择配色，不能继承旧底色的通过结论。
- 检查脚本只等待实际可见图片解码；需要检查完整区域时实际滚动再等待，给故障保留明确结果。屏外懒加载等待不能无限阻塞，也不能把尚未加载的屏外图片直接判为缺图或通过。
