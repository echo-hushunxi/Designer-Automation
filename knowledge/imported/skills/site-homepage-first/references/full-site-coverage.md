# 全站覆盖与漏审预防

仅用于首页驱动创作的全站延展、完整验收和适用维护。并入既有 HFG01–HFG03 和集中问题包，不增加审核阶段，不给其他生成模式新增要求。来源：`generation/coupon-skill-audit-20261016-ae6Mnx/` 的漏审发现与 `generation/duo-skill-repair-20261016/` 的修复和实测。历史结果不能继承为新候选通过。

## 从实际页面推导覆盖

先枚举导出路由、启用模块与冻结合同，并读取用户指定技能的相关页面合同及最终验收要求。不要从审核工具默认的 home/store/listing/detail 四族反推全站已经查完。FolioPerks / RivetDeals 本次实际启用17族：首页、商家、优惠详情、全部优惠、商家目录、分类目录、分类详情、搜索、节日目录、节日详情、指南目录、指南详情、About、Contact、Privacy、Disclaimer、Terms。这是本次覆盖清单，不是未来站点的页面配额；启用排名、测评、Reward 或其他用途时纳入对应合同。

在原报告中为适用项记录 `clause / family / route / width×height / state / build / revision / artifactHash / evidenceId / result`。检查范围由所选验收模式确定，实际断点、长内容和关键状态按风险补查。结果使用 pass、fail、not-run、not-applicable、deferred，并说明后面三类的原因。缺失证据不能默认为 pass；延期须关联当前用户授权，不沿用到下一项目。视觉判断另引用实际看过的像素，脚本成功、计划完整、文件存在不能代替。

## 本次漏项如何预防

| 检查对象 | 制作决定与最终实查 |
| --- | --- |
| 节日详情 | 按合同提供完整节日导航、当前项和真实计数；查看桌面侧栏及手机堆叠，检查0/1条结果和运行时到期后计数。普通分类侧栏不能代替节日导航。 |
| 指南详情 | 对照实际合同检查标题、封面、引言、编号建议、推荐内容和侧栏的业务顺序；保留来源正文与事实。无热度数据时用写实导航名称，不编造热门排名。目录卡片通过不能替代文章详情。 |
| Contact 与信息页 | 读取正文及真实配置，实际检查 mailto/支持入口与页脚目的地。用户授权邮箱格式可形成配置；邮箱链接有效不证明邮箱已开通或能收信，不作虚假服务承诺。 |
| 主券操作顺序 | 有码、无码分别实看合同规定的标题、代码、操作、期限和状态反馈顺序，不能只凭内容都存在判断。自动、降级、拒绝复制及刷新重新掩码分别操作；拒绝场景显示可完整选取的代码不等于复制成功。 |
| 搜索与分类 | 使用真实匹配、无匹配、清空和标点输入，检查转义、关键词强调与动态链接；分类按合同展示商家数量和标题，券数不能替代商家数。到期后保留搜索输入及焦点，计数同步。 |
| 首页卡片与按钮 | 先看本站已有风格再设计；按每个可见标题板块选字段、分配 Logo 本体、优惠重点和操作。检查整排、整组、末行、重绘和手机，不只看一张卡或外框。跨站比较实际构图、按钮构造与字体层级，不能只换色。 |

板块可以按用户授权选择字段，但须对照该次冻结合同和基线明确允许省略的字段。不能只在新设计计划写“省略日期”就当作获得授权；本次 Folio 简卡最终恢复真实日期，以独立、紧凑的轨道保持层级。该修复不意味着未来所有券卡都必须展示全部信息。

## 工具适用性与真实执行

- Pug 检测及 structure-lock 脚本用于其支持的项目结构。独立 HTML/ESM 不能伪造 `.pug` 文件使脚本变绿，也不能把检测器找不到模板当作页面缺失；记录工具不适用，并以原始源码/数据备份、字段与 hooks 对照、实际模块顺序、路由和分支操作完成等价语义检查。不得把不适用写成脚本通过。
- 检查打包后脚本启动与运行时错误，再评估计数和画面。搜索或复制局部可用，不能证明初始化、到期刷新与其他模块全部执行。修改生成辅助脚本时注意字符串替换中的 `$` 语义，实际构建并重跑受影响状态；失败候选与错误回执保留。
- 并行浏览器共用同一作者/构建时，可替换的 live-view 路径可能被另一窗口更新。报告图片从各自不可变 evidenceId 的 PNG 取副本，并校验身份与哈希；不能把最后一个 live-view 文件当成所有状态的截图。模拟时间后若DOM和截图不一致，保留不一致，真实键盘/滚动促发绘制后重取一致凭据，不凭DOM单独记视觉通过。
- 图片先按实际可见区域解码，检查整区时实际滚动。Logo 质量需看本体、完整性与实际绘制大小；`object-fit:contain` 的外框宽度不等于图片绘制宽度。判定器错误应保留反例，修正测量逻辑并用真实通过/失败样本验证，再产生新回执；不能裁标、缩字或改站点迎合错误判定。
- 按真实业务角色检查尺寸：商家目录卡选择器命中，不证明商家详情的身份区也被检查。单独测量 Logo、分类、店名、数量、Visit store 所在身份区，并对照该候选冻结的限高及字号/点击要求；不能继承本次原生选择器漏掉身份区的“0失败”。用完整商家集合及长分类实际复查窄屏，标题需要宽度时重组区域，不能缩字或裁切。
- 1200px 规则测页面级主容器，含侧栏及间距；Header50px和手机12–14px边距测真实内容与控件。导出全部 HTML 检查 TDK 及链接，实际解压 file 页面验证动态搜索、加载、独立链接、整卡、键盘和真实拖选。HTTP预览不能替代离线执行。

## 闭环

交付前重读本次所用技能的验收条款，核对覆盖矩阵无遗漏；将原问题、复验新发现和回归分别对应到精确候选。修源码后建立新构建，补齐受影响复验及原有关键检查，不复用旧截图冒充新构建。独立审核结论、原生审核状态、可下载产物与用户审美确认分别说明。未测项或主要缺陷仍存在时，如实报告，不能靠高分、历史通过或下载授权放行。
