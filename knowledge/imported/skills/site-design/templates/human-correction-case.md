# 人工修正记录模板

复制到对应站点的开发资料中填写；未知项保留未知，不把模板提示当成已完成证据。

- 案例ID / 站点 / 原始revision或build / 修正revision或提交：
- 人工原始反馈与来源：
- 区域用途 / 页面 / 实际视口 / 数据记录ID / 页面状态：
- 原始产物证据路径、哈希、实际观察：
- 修正产物证据路径、哈希、实际观察：
- 已确认的修正原因；未确认的推断分别列出：
- 分类：既有硬规则违规 / 通用制作方法 / 该站偏好 / 待验证：
- 生成能力缺口：为什么此前设计或实现会产生这个问题：
- 可迁移的制作决定：下次在构图、内容或组件阶段怎样预防：
- 不能推广的本次造型、尺寸、数量、文案或数据变化：
- 受影响的同站组件、页面及客户端重绘路径：
- 实际复测：精确候选、route、width、state、evidenceId、结果及未检查项：
- 人的主动收尾时间、机器等待、自然收尾历时：
- 可机器检查的断言、对应测试及真正放行调用点；没有则明确尚未实现：
- 独立视觉判断的复测目标和对照样例；不能以一个数值代替：
- 共享经验变更：适用lesson ID、作者/审核入口、版本或hash、新运行验证状态：

完成标准：只有已确认且修正复测成立的方法才能写成成功经验；没有实际门禁调用不能写“已阻断”；没有新站结果不能写“稳定性已验证”。站点偏好留在该站，公共方法归入production-lessons/人工修正能力包，明确硬错误另落实到测试和执行门禁。
