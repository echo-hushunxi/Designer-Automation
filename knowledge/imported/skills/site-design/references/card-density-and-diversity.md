# 卡片密度与构图差异：生成、审核共同执行

适用于所有含卡片的 Coupon 页面，不限首页。版本 2026-10-23.4。来源是用户对四站第二屏、手机端同构及 Paloma 小 Logo 的明确退回和实际页面；这是排版防错方法，不是统一皮肤，也不声称其他页面专项已全部实测。**本规则只管显示尺寸、排版、间距、卡片与操作关系；不把 Logo 源图分辨率、锐度或素材溯源列为生成与审核门槛。**

首页先读[四张参考的处理方法](home-card-reference-methods.md)。2026-10-20 用户已确认：学习分组、容量、重点与跨端重组方法，原创设计本站卡片；同用途同断点固定规格，摘要可取舍并截断，全文在详情可达，商家 Logo 展示区至少70×70。下列现行条款已按该决定调整。

## 必须保留的边界

- 跨站不能把同一卡片模板换颜色、圆角、Logo 后称为不同设计。跨页面按任务组织：首页浏览券、店铺券行、详情主券、推荐券、商家、分类、文章各有职责；不能全部套一种券卡。同任务在本站复用组件是正常一致性，不要求每个 URL 发明新皮肤。
- 保留本站已确认的构图、展示字体和可辨识按钮；本次授权纠正的异形动作、普通信息字体及对齐按公共底线调整。差异应在信息分组、图文关系、阅读顺序、日期位置、操作与内容关系等实际设计中成立。颜色和装饰切口不能单独证明差异。
- 真实日期/数量、业务状态、可读性及点击区域继续适用。摘要卡按用途选择可见字段并在既定文字区域省略，保留完整数据、可访问名称及正确全文详情。不得缩字、改成不明图标或截断实际优惠码及完整详情来塞内容。主券代码区及领取流程不降格为普通推荐行。
- Banner 最大高度 PC 480px、手机 400px，是上限而非固定高度。现有站只在授权范围采用新要求；历史冻结包不追溯修改。

## 制作前：逐卡型决定，不写空泛口号

在源码 `docs/card-layout.json` 使用配套 [计划模板](card-layout.template.json) 记录：页面族、实际组件/选择器、职责、必需字段、PC/手机图文和操作分组、跨端尺寸边界、文字容量与溢出处理、主要对齐轴、短内容处理、长内容例外，以及本批同类卡的实质差异。相同组件可列多个使用页；没有卡的阅读页明确记录不适用。

先用真实最短标题、最长标题、长商家名、日期未知/过期/无码样本排代表卡。先用真实内容验证合理的卡片家族容量，再锁定同用途同断点规格、列数与分组；不能单张随内容无限撑高，也不能预留过大的卡壳再把内容分散填满。页面间距分四层记录，最终看相邻可见元素的实际边界，不能只读 `gap`。

普通浏览券起稿可用信息组内部 4–8px、组间 8–12px、内边距 12–16px作为制作目标；它们不是覆盖所有卡的硬门槛。主券、商家身份、活动及文章采用各自用途预算。标题和商家名 16–20px、日期等普通文字不低于14px、主操作实际点击区域至少44px继续适用；描述仅在允许的角色出现。

## 防止本轮复发

1. **不得为每个字段强制共享行高。** 商家、标题、日期、按钮全部进入跨卡 `subgrid` 会使短标题被最长同行撑开。只有证明没有产生空行/空洞时才可使用共享轨道。优先稳定外框、约定文字容量和关键对齐轴；短标题可保留合理行位，但不能把每个字段撑成大空带。
2. **操作必须与作用对象成组。** 不让一句标题上方挤在角落、按钮独占远处底行。可按本站构图把按钮并入侧边操作栏、日期操作行、票根或内容后的紧邻动作；不是全站统一选择其中一种。
3. **固定容量与合理密度同时成立。** 普通优惠标题／商家名固定单行省略，同家族保持一致行高和卡片尺寸；摘要超出省略，不单张撑高。短内容可保留对齐所需余量；大块空洞、逐字段拉伸和孤立按钮仍失败。完整详情及代码区保留全文能力，不套摘要裁切。
4. **手机必须重新排组。** 逐张看 Logo 与标题相对位置、辅助信息与操作关系。不能把 PC 的四行布局原样堆叠，也不能绝对定位按钮去盖住长标题。窄屏容纳不了时调整整组列数、字段分组或该断点的摘要容量，并保留清楚的操作组。
5. **不靠无关内容填洞。** 不新增装饰眉题、虚假描述、数量、徽章或多余说明来占满卡片。
6. **重组后检查有效级联。** 旧子元素的 `grid-area`、列号、`justify-content`、`min-height` 不会随新父容器自动消失；可能在新文字组内生成隐式空列，或把短字段居中推开。逐项查实际计算样式及真实边界，不能只看新加的外层 CSS。独立商家链接若产生44px空行，可在保持官方 Logo 的独立店铺入口后，将商家/完整优惠/日期组成一个明确的本券阅读入口；不能把仍然独立的操作目标缩到点击底线以下。
7. **状态分支不能误用领券网格。** 有码主券、无码入口、不可用旧链接及复制反馈分别检查。新码框两列布局只能作用于真实的代码/操作组，不能把“优惠不可用”的标题、说明和店铺入口挤进同一网格。核对内部 `min-width` 与真实窄屏单元宽度；根页面无横滚不代表码框和按钮未互相遮挡。初始掩码不应独占多行，真实长码必须完整、可复制并在自身区域自然换行。
8. **按实际正文宽度切换构图。** 固定 Logo、操作侧栏、内边距与栏间距相加后，正文仍须能正常读词；不得把正常英文单词挤成单字母文字柱。检查每个列数切换点两侧的最短/最长真实卡，特别是刚恢复多列的一侧。无横滚、字体和热区合格不能豁免文字柱或短卡空洞；改列数或信息组织，不能缩字或把摘要截成无法理解的碎片来塞入。
9. **同卡型跨页面和重绘必须复验。** 首页紧凑不能证明全部优惠列表也紧凑。逐一检查实际使用该组件的手机列表、活动、搜索及相关推荐。把商家等文字放入自然阅读组后，还要确认它没有继承独立链接的44px轨道、居中或旧网格坐标；44px约束作用于真实操作热区，不把非独立操作文字撑成空行。
10. **Logo 本体、链接外框和网格槽分别检查。** 图片70px不代表外层也是70px；两者分开测量。核对链接自身的宽高、内边距、最小尺寸和所在列；外框不得无故撑高卡片或侵入正文/其他操作目标。装饰不计入点击范围，真实链接不能靠外层覆盖相邻文字获得热区。相同渲染器的不同子卡型、筛选及加载结果也要复验。首访冷加载、第一次滚入视区与缓存后重载分别记录；固定身份图的加载策略须避免首次可见时反复白框，长列表仍可合理延迟加载。只有外框尺寸合格不代表 Logo 已显示；保留首次失败及后续成功证据，不得仅用重载后截图掩盖首次缺图。
11. **差异必须在每个实际端成立，不能用 PC 差异替手机交差。** 批量起稿前，按同用途列出每站手机的字段分组、阅读顺序、Logo 相对优惠的位置、日期所属信息组、操作与优惠的关系；先画简易线框再实现。先并排看同宽真实手机卡，忽略颜色、圆角、阴影及按钮装饰；如果仍是相同的“左 Logo／右商家标题／下方日期加按钮”，就属于同构，不能因为桌面不同而通过。更换 DOM 标签或 grid-area 名称也不是构图差异。不是强迫任何两个元素都不同，而是主要信息与操作的组织确有区别，且仍易读、紧凑、可操作。
12. **主动比较，不等用户指出。** 生成者在交接前提交逐端的同用途并排证据，独立审核者先看图写自己的分组判断，再读作者命名；分别记录 PC 与手机的差异结论。卡型首屏、普通券、次级券、季节券和重绘结果按真实适用范围覆盖，不能只挑差异最大的特例遮住普通卡同构。缺同宽手机对照是 not-run；实际同构是 revise。四种具体构图只是某次设计选择，不把它们做成后续固定轮换的模板库。
13. **紧凑不等于保留细碎小目标。** 除主 CTA 和 Logo，还要枚举商家、短标题等实际独立链接，验证真实命中范围及键盘入口。不能因主按钮44px就漏掉约22px高的独立文字链接，也不能给每字段加44px空行补数。可保留独立 Logo 店铺入口与主动作，把其余字段作为本券整体阅读入口内的文字；该入口必须实际可点击、可键盘进入本券，重绘后继续成立。不能只删 href 就宣称修好，也不能用透明目标覆盖 Logo／按钮或相邻券来扩热区。
14. **紧凑与差异不能靠缩小品牌显示。** 制作前逐角色、逐断点写 Logo 在页面上的图片/外框尺寸预算并对照适用来源；实际商家图片展示区在PC及手机均至少70×70 CSS px，框与热区不能代替；最大尺寸按用途预算，避免挤占正文。明确硬数值、起稿参考和本次选择分开。44px热区不等于Logo视觉下限；同组等框也不能替代实际显示大小。对图形、长字标和内部留白大的商家一起看最终布局，静态、筛选、加载和末卡都检查。重新分配整卡空间，不靠缩字或把长标题挤成文字柱。用户已否决 Paloma 48px 手机身份角标及对应构图，旧内部ready不覆盖用户否决；不能只放大空框或只改尺寸而不重看整卡。
15. **审核最终生效尺寸和每个子卡型，不审核声明值。** 记录外框、实际 `<img>` 计算宽高、可见标志占位与周围正文/按钮的空间关系；旧样式可能让新88/96px框内图片仍停在64px。仅判断显示过小、错位、压字、空框撑高等排版问题；不测源图 naturalWidth/naturalHeight、锐度或素材来源。特色券通过不能代替普通券、PC 通过不能代替手机；跨站比较逐端逐子型执行。长商家名在品牌栏被拆成单字母或标题与日期间出现无语义空带时，先调整分组和可用宽度，不能缩字或把日期移到标题之前凑紧凑。

## 审核：必须有实际证据

先看最终产物独立像素，再看作者计划。整轮一次汇总，作者集中修复后交新候选；用户明确退回的构建不能沿用原 pass。

- 枚举启用页面族到实际卡组件的映射，首页首两屏和下面连续券组必须看；再看店铺、列表/搜索、主券及推荐、活动、文章的适用卡型。静态输出与筛选/搜索/加载后重绘都检查。
- 每卡型至少比较最短和最长真实内容、同排最短与最长卡、末行；PC、常见手机、320px及改变列数/分组的断点邻域。证据写明精确候选、路由、视口、状态和截图；未执行就是 not-run。
- 记录实际内容末行到日期/操作的间距，以及外框中最长无内容带。大于本卡常规组间距两倍、或出现约24px以上无语义空带时触发人工复核，**不是自动失败阈值**。核实是 Logo/必要代码区/长标题/有意主视觉，还是共享轨道、空行、过大的固定高度、孤立动作造成。无法说明空间用途且实际空散，必须 revise。
- 同时验证按模块声明的可见字段、摘要语义及全文详情可达、按钮不重叠不越界、点击区域和文字底线、Logo 实际显示占位、真实内容及状态。根部无横滚、卡框等高、按钮在同一基线都不能单独支持 pass。素材清晰度属于另行明确要求时的素材审核，不影响本排版轮次结论。
- 把本批同用途卡并排比较；记录构图和信息/操作分组的实际差异。再比较本站不同用途卡的任务是否清晰。维护不强迫重做未授权身份；新设计不能只换色。
- 报告分开记录“尺寸/内容检查”“密度视觉判断”“跨站及跨用途差异”“离线/交互”“用户是否认可”。自动检查不签发审美通过。

模块级执行（2026-10-23）：不能把密度只做成首页一个汇总项。每个实际模块/子卡型在PC、手机、320px分别记录目的与层级、短长容量、空间/动作归属、整组与末行、跨端构图；真实实体 ID 与 short/long/last-row 角色进入冻结 sampleCases。作者与独立审核分别提供 observedSamples 和 group/short/long/last-row 的可读像素引用，可复用同一整组图。独立 inventory 核对家族、样本与额外语义模块；尺寸及稳定性再多也不能抵消缺少模块视觉检查。Jingle 普通券/季节券曾在整页和礼签检查通过后仍有150px宽卡、178px手机卡的空散问题，此负例要求把普通与特色家族分开逐组实看，不规定所有站统一尺寸或布局。

同日用户针对 Aster 手机券行补充：采用左 Logo、右侧标题/日期的横向卡时，领取按钮靠卡片右侧操作轴，不能因为标题短而跟着阅读组停在左侧。作者与审核须核对320px、常见手机、短长卡和末行的真实按钮右边界，并验证44px热区与全文入口；其他构图保留本站用途。具体制作方法见 home-card-reference-methods。

## 负例与回归

2026-10-20 用户退回 RivetDeals、FolioPerks、Jingle、Paloma 首页第二屏。旧报告已通过等高/字号/按钮尺寸，但四行共享轨道把内容撑散、动作孤立，证明上述数值不足以判定排版合格。四个被退回构建分别为 `b-67dbb335-613a-4010-95f5-bc5b0e577585`、`b-85e55415-838e-436a-8d65-d76dce1365d8`、`b-34b88231-2ce0-4145-b0f6-0cb8477f8709`、`b-a1ce15d3-b805-40bc-96d9-c5b6297c5d32`。项目中的证据在 `engineering/card-density-repair-20261020/baseline.json` 与 `before/screenshots/`；可携带包只带方法和构建标识，不假装包含这些运行截图。

后续审核必须能识别这一反例，并在新候选实看相同卡型。规则覆盖不意味着以后绝无缺陷：发现同类空散继续返工，不能凭已读取 skill 直接放行。

同轮独立复验还发现：Folio在761/768px固定72px Logo与140px侧栏挤出文字柱；Rivet在1051px刚恢复四列时短卡空洞复现；Rivet手机全部优惠在首轮漏查；Jingle虽然有阅读组，后加载样式仍让商家居中并占44px。以上是明确负例，检查必须针对实际构图切换点和最终有效级联，不能只检查320/393/1440端点或作者新写的CSS片段。具体独立证据留在同次运行的 `independent-review/round-2.json`，可携带包仅带此防错方法。

Paloma 旧审核候选 `b-b0cda049-9d16-4997-994a-c85d1b36c5cb` 曾记录三项问题：Fresh 外框88/96px但旧 CSS 仍把实际图片限制在64px；Gifts 中 Gourmet Gift Baskets 低分辨率素材被放大；PC 普通券仍与 Rivet 的左 Logo／中字段／右按钮同构。历史证据保留在 `engineering/paloma-logo-layout-20261020/independent-review/`，其中素材清晰度一项不再作为本**排版标准**的必检或否决依据。今后重点核对最终生效的显示尺寸、卡片占位、PC/手机逐子型同宽对照；新候选另取证，不能沿用旧候选的 pass。

Paloma pantry 的后续漏检：64px Logo 本体在96×88px链接里，实际网格槽只有64px。旧链接尺寸/内边距增加24px首行高度并侵入正文区域；商家和标题本身均为正常行高，不能误诊为文字44px轨道。复验必须覆盖初始、筛选、加载和末位卡，不能只看Fresh picks替代普通券子卡型。独立证据见同次运行 `independent-review/round-3.json`。
