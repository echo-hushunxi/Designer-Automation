# 制作阶段的防复发经验

适用于新设计或明确要求重做的区域，不要求重做已确认旧站。作者在构图前选择适用条目，在交审前用实际页面验证。数值检查只能定位问题，不能证明视觉质量。本文记录失效模式与验证方法，不提供固定皮肤、按钮、配色、插画题材或页面模板。

2026-10-13补充：[人工修正能力包](human-correction-learning.md)记录H01–H08：内容职责、手机卡片构图、识别与点击、信息取舍、推荐区域、侧栏职责、跨端数量及同站迁移。它来自Sunclip与人工Couponrite的实证；制作前选择相关方法，复验时检查是否再次出现同一失效模式。共享workflow同时提供本索引与能力包的全文/hash，不再仅靠协调者私有提醒；检查项尚未全部成为机器门禁，不能宣称一小时或质量稳定性已达成。

## 交审前留下可复核的自检

在本次运行记录中保存与确切候选 buildId 绑定的作者自检：适用 lesson ID、实际 route、视口宽高、页面状态、工具产生的 evidenceId/画面路径、观察和仍未解决的问题。不伪造凭据，不把作者自检写成独立验收。缺少实看证据就是未检查。

发现问题时先修可编辑 source，再构建并重看对应场景；上一构建的截图不能证明新构建已修好。用于申请通过的候选应先解决作者已知的主要缺陷；可浏览的失败候选仍需交到独立只读诊断，不能获得ready/pass。修复上限停止改页面，不取消失败审查。非阻塞建议也应判断是否值得本轮处理，不能为了清空记录机械改变设计。独立审核仍负责发现作者盲区及判定整体完成度，不能保证所有审美探索一次通过。

## 每轮反馈如何继续沉淀

1. 协调者保存原反馈及 exact buildId，区分硬规则违规、重复的已知缺陷、新视觉问题、非阻塞建议和未执行检查。
2. 对值得复用的项记录：观察与证据 → 已确认原因或待验证假设 → 原作者的修改 → 影响范围 → 新构建的实际复测。只有验证过的修复才写成成功经验；仍在尝试的办法标为待验证。
3. 将跨站可复用的预防方法补入这个共享技能；站点独有的偏好和具体造型留在该项目设计记录。一个协调者归并公共经验，作者不要并发改中央规则。
4. 后续作者制作前读取相关经验，审核者先形成独立第一印象，再检查适用条目是否复发。重复发生要记录“已知问题复发”和缺失的预检环节，不能只换一种文案再次提醒；统计只针对实际检查过的项，不能杜撰改善率。
