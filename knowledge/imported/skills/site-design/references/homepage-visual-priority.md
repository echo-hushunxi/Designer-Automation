# 当前优先级：先让 UI 成立

用户已明确：当前最重要的是 UI，实际页面必须在视觉上过得去。此约束适用于新站和明确要求重做的首页，不授权重做其他旧站或已确认区域。它规定设计与验证的先后顺序，不降低真实数据、业务行为、可读性和离线交付要求。

## 什么才算方向成立

后续首页的最低视觉完成度以用户于 2026-09-30 明确认可的 MerryPerks 与 Eve & Ember 首页为基线，详见公共 workflow 的 `ownerHomepageBaselines` 和 `policy/owner-homepage-baselines.json`。生成者与独立审核者必须实际查看保留的桌面、手机画面，比较原创主视觉、首两屏主次与购物吸引力、主题化的真实卡片/按钮、背景与字体的整体关系，以及移动端重排。新首页至少达到这两套的完成度，不能以功能、页数或数值通过替代这一要求。它们是质量基线，不是两套固定皮肤：不强制复用圣诞题材、红白/深蓝配色、纸卡、构图、按钮或列数。已认可首页扩展内页时保留其视觉优点；首页认可不等于整站验收。

- 首页必须有完成度足够、与优惠购物主题相关的原创促销主视觉。可以是摄影、插画、拼贴或以真实商家/优惠为核心的原创商业构图；标题、优惠信息和操作保持真实 HTML。不能把原创主视觉误解为每站必须生成人物/商品大图。用户当前校准的 Couponbon/Couponister 商家主题构图是有效方向；单纯放几个 Logo、小图标、代码遮罩、搜索框或无关大标题并不自动达标。拒绝 Poplane 拼贴海报方向及鞋子插图。
- 主视觉、配色、字体、精选优惠、品牌入口、按钮和留白需要共同形成一个站点的视觉语言。不是放一张图就达标，也不统一为左文右图、购物袋、某种圆角、配色或固定高度。
- 首屏让用户看懂网站及值得点击的内容；第二屏承接浏览欲望，精选与普通内容有主次。目录、筛选、长段说明和重复信息条不能独占首页体验。
- 图片要有关联、质量足够、与文字及按钮构图协调，并有适合手机的裁切或重排。不要靠无关图片、装饰性小字、虚构销量/认证/折扣营造热闹。
- 不同站点仍需有自己的风格，但“与另一套不同”不能证明好看或完整。商业完成度优先于为凑差异而制造奇怪构图。

## 先实看代表首页，再扩展

1. 生成者实际查看用户提供的优秀参考首页和已认可的旧站，研究首两屏；不能只读设计 JSON 或把参考网址列入计划。当前主校准参考为 Couponur、Dealmerica、Couponbon、Couponister；旧版 MerryPerks/Eve & Ember 作为保留的完成度基线。记录实际查看的 URL/buildId、视口和具体优点；每套站各自的布局、卡片、按钮和视觉语言都是优点，不把其中一套固化为统一模板。不照搬其广告空白、失效内容、未经证明的宣传或已禁止的装饰文案。
2. Kimi 作者先完成一个有真实内容和主视觉的代表首页，查看桌面与手机的首屏、第二屏。准备代表店铺/优惠券详情以确认品牌语言可以延续，但先不要把弱方向扩展成整套设计。
3. 委派独立 `site_design_review` 做 **homepage-direction** 阶段评审。提供确切 buildId、参考材料和范围；不提供预定通过结论。审核者先看实际页面，再看计划，记录主视觉完成度、第一焦点、配色与字形关系、内容主次、真实 CTA、留白/密度、第二屏衔接以及手机表现。与参考的实际画面对照，不依靠计划中的美学解释。该角色的 `site_browser` 只访问本地冻结构建：Brightside、Tagtally 等本地参考由它亲自打开；外部参考由具备外部浏览能力的协调者实际访问并保存原始页面截图及 URL、采集时间、视口，审核者用 `read_image` 独立查看这些画面。外部截图审阅不冒称角色亲自访问外站，不伪造 `site_browser` evidenceId 或本地 referenceVisits；缺参考材料如实记录并补齐，不要求用户另行截图审批。
4. 早期审核者返回方向 `established`、`revise` 或 `not-run`，附具体页面/视口、真实浏览证据与问题。这是阶段性反馈，不是完整报告的 `pass`，不得调用 final submit 来冒充全站验收。协调者保存原反馈与确切构建身份后，只有视觉方向 established 才继续扩展；任一主要视觉问题或缺少实看证据都先退回原作者。
5. 全站完成后仍按正式格式做全部页面、功能、事实、同批差异、响应式、离线和保全验收。首页好看不能抵消详情缺陷，技术检查通过也不能抵消首页差。

不要用增加更多数值指标替代审美判断。没有横向溢出、达到字号、推荐数量够、复制可用、页面很多，均不证明首页视觉成立。纯目录/货架/信息看板/文字专栏即便可操作，缺少所需的购物主视觉与整体完成度仍需返工。

## 素材与能力缺口

生图工具/Provider 不可用时，保留其明确限制。可使用获得授权且适合页面的素材或由 Kimi 原创、完成度足够的插画；不能把缺素材改写为无 Banner 的“极简风格”，也不能谎称插件已经出图。若所选方向必需的素材仍无法获得，该方向保持未完成，不能靠说明放行。用户明确要求生成图片时，替代方案不能冒充已满足生图要求。

## 本批已经收到的用户判断

2026-09-28：Storeline、Aislewise、DealDeck、Dimepress 当前首页被用户否定，应重新设计主视觉和首两屏；不能只补数量、字号或间距后继续交付。Giftlane 的方向可保留打磨，不代表整站已通过。保留原构建及源码历史，仍由 Kimi k3 作者实施，详情业务框架内的设计自由继续保留。
