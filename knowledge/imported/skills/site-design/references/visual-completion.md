# 全页面视觉完成度：制作与独立审核

版本：2026-10-22.2。适用于所有页面的 new-design、reuse、reference-rebuild，以及 preserve 的授权修改区域和受影响回归。用户已确认：禁止无效空洞，保留有效留白；统一质量，各站独立风格；合理精细优先于猎奇；规则、执行入口与审核覆盖一起增强。追加要求图文对齐、水平关系和视觉平衡。历史候选继续使用其冻结版本。

本方法补充既有公共工艺、布局预算和页面专项，不覆盖真实数据、首券完整、摘要容量、Logo、字号、操作和业务状态要求。它是一套判断与制作方法，不是统一皮肤，也不表示尚为 partial / pending 的页面专项已经完成。

## 先组织内容，再决定外观

作者在现有设计计划中说明：这页服务什么购物任务、第一焦点是什么、下一步是什么、哪些信息属于一组、PC与手机怎样分配空间。用实际短长内容完成代表区域，在浏览器检查后再扩展同类组件。新站沿用先首页方向、再扩展全站的独立审核顺序；局部维护沿用当前身份及授权范围。

合理的常见购物版式允许使用。品牌辨识度来自内容选择、构图、字体、比例、颜色和操作语言的连贯组合；不要求每个模块发明新布局。跨站仅换名称、颜色、字体或圆角仍不足以成为独立设计，也不能用强行错位、额外装饰或扭曲阅读顺序制造差异。

## 六项制作判断

| 判断 | 在实际页面里看什么 | 常见失败与修正方向 |
| --- | --- | --- |
| 整页构图与焦点 | 忽略细字和装饰后，主要优惠、品牌对象、下一步操作及模块主次仍可辨认；重要性与占地匹配 | 所有模块同样醒目、大片装饰挤走优惠、侧栏抢过主内容。先调整内容选择、分组、比例和阅读顺序，再处理装饰 |
| 有目的的空间 | 同组信息更容易被看成一组；卡内、卡间、标题到内容、模块间的距离形成清楚关系；操作贴近所属对象 | 短卡被最长卡撑空、按钮被推到底、嵌套padding叠加、重组后遗留空轨道。查最终行高、min-height、stretch、auto margin和容器空槽，修根因而非统一减gap |
| 字体层级与容量 | 优惠、商家、日期和操作各自清楚；实际字体、字重、行高、文字轨道与换行共同工作；手机长标题仍能理解 | 数值合格但标题成为窄文字柱、按钮标签孤字换行、辅助信息抢焦点。重分配真实宽度或重组，不缩小既定字号/Logo/热区、不截断首券 |
| 色彩关系与状态 | 背景、阅读面、正文、辅助信息、品牌强调、主次操作及语义状态有明确角色；大面积色块与强调对象协调 | 高饱和区域相互争夺、辅助标签比主操作更强、浅字在浅底消失、hover/过期状态混淆。调整面积、明暗、强调程度与用途，不凭颜色数量或色名判优劣 |
| PC与手机编排 | 容器、阅读轴、图文比例、分组和操作位置适合当前宿主宽度；窄屏、中间宽度和实际断点两侧成立 | PC差异明显但手机全部退化为同一拥挤卡；只改列数而保留旧高度；某个中间宽度空散。分别编排内容与动作，检查连续模块和末行 |
| 图像与品牌协调 | 实际采用的图像、图标、字体、边框、按钮和细节属于同一设计语言；图片题材及裁切帮助理解当前内容 | 主视觉与优惠无关、装饰图标抢焦点、首页与内页像不同产品。回到内容与品牌选择，保留成功部分。无需为凑检查项加入照片或装饰 |

大留白本身不是失败。它若帮助分组、阅读、主视觉或有意构图，可作为有效留白保留；若使内容失联、连续浏览断层或挤压必要信息，就是应修正的无效空洞。约24px或两倍组间距仅沿用已有规则作为触发实看的信号，不是全页强制上限。密集目录也可以精致，宽松版式也必须让购物任务清楚。

颜色的可测底线与审美判断分别记录：既有普通文字4.5:1、大字3:1等要求继续生效；先确认文字角色和最终实际背景，透明叠层、渐变和图片上的文字不能只用声明色推算。无法可靠测量时保留未测项并实看，不填写虚构比值。对比度合格仍需判断配色面积、主次及品牌协调；不设所有站统一色板、字体或装饰黑名单。

## 图文对齐轴与视觉平衡专项

来源区分：[Carbon对齐线](https://www.carbondesignsystem.com/building-blocks/foundations/2x-grid/overview#key-lines)提供共享水平/垂直轴的方法；[Atlassian光学校正](https://atlassian.design/foundations/spacing/#use-optical-adjustment)说明视觉重量可能需要调整标准间距；[CSS Box Alignment工作草案](https://www.w3.org/TR/css-align-3/#baseline-values)与[MDN align-items](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/align-items)用于区分盒对齐、中心对齐和文字基线。以下场景选择与审核要求是本项目的转化，不是这些来源规定的统一版式。

### 三个层次分别判断

- **结构对齐**：容器边缘、图像槽、文字轨道和操作组沿声明的水平/垂直对齐轴组织。测实际内容边缘，不能仅测带padding的外框。
- **文字基线**：同一阅读行中不同字号、数字、单位或标签按适用的真实文字基线组织。外框同顶或中心相同不证明基线正确；不把图片底边当文字基线。`baseline`等CSS能力须在实际浏览器和最终字体下检查，不把工作草案所有属性当成已通用支持。
- **光学平衡**：根据可见图形、字形、图像内部留白和视觉重量微调局部位置、比例和间隔。矩形框相等或几何中心相同后仍需实看；不能用计算样式推导“视觉重心已经平衡”。

### 按内容关系选择对齐方式

| 图文关系 | 要声明的对齐与平衡决定 | 必查反例 |
| --- | --- | --- |
| Logo/图片＋短标题或紧凑信息组 | 选择图像与**整个信息组**的中心关系，或有理由的内容顶线；分清对齐对象 | 只对标题一行居中，日期和操作加进来后整体下坠；同样大的图片框中可见Logo偏一侧 |
| 图片＋长标题/多段正文 | 选择图片内容顶线与文字组开头的关系，或经实看成立的整体居中；为标题保留可读轨道 | 全局`align-items:center`让图片随正文增长而漂移；为齐底强拉图片或保留大片空带 |
| 同行数字、单位、日期和标签 | 同组按文字角色检查基线；标签独立成组时说明其与正文的关系 | 数字与单位底部参差、标签因不同line-height悬浮；强求所有字形顶边相同 |
| 按钮内图标＋文字 | 操作作为完整组合保持平衡，检查可见字形、图标本体、间隙和两侧内距 | 图标框居中但箭头可见图形偏上；图标把标签挤偏；每个按钮各加不同偏移 |
| 连续卡片和网格 | 同一用途沿一致的图片轨道、文字起点和操作组组织；不同内容长度仍有连贯阅读轴 | 卡框齐平而标题起点左右漂移；长标题换行后文字/动作压进图片；为同行齐底拉大所有短卡 |
| 大图/主视觉＋文案 | 图像主体、文字量、明暗、色块面积和CTA共同平衡；比例由内容任务决定 | 左右机械五五分、图片压窄文案、大片浅图对上挤成一柱的深色文字；裁切后主体背离文案或挤走操作 |

同一组件在PC、手机可以选择不同的图文关系，先按内容与宿主宽度重组，再复核轴线。顶部对齐、居中、非对称各有适用场景，不强制全站垂直居中、同高或五五分；图文视觉重量也不以面积相等判定。

### 制作、自检和独立复核

1. 在现有卡片/页面决定中写明：谁与谁对齐、用内容顶线/中心线/文字基线中的哪一种、文字组包含哪些字段、PC与手机怎样变化。有意错落也要有阅读目的。
2. 最终字体和图像加载后，看图片槽、实际图片、可见Logo/主体、文字行盒及可见字形。透明或固有留白不能用外框尺寸掩盖，也不通过裁剪、变形或改色官方Logo来消除；保留既定Logo、字体与热区底线。
3. 短/长标题、长商家名、日期有无、图形标/长字标和实际断点两侧分别检查。文字由一行变三行时，重新看整个图文/操作组，不只确认没有溢出。
4. 可用临时水平/垂直辅助线看内容顶线、中心线和重复阅读轴，随后关闭辅助线查看正常页面。测量与辅助线不能替代正常像素判断，调试线不进入最终交付页面。
5. 光学校正限定在有依据的局部组件，记录对象、方向、偏移与原因，并同步检查热区、遮挡和邻项；不能给全站图片统一translate或为每条记录硬编码补丁。预算允许有说明的非零偏移，不把所有轴强制为0。

公共inspector的`alignment`支持left/right/top/bottom和center-x/center-y；后两项测元素盒的水平/垂直中心偏差，可绑定图片与声明的文字组。它不能自动识别透明图片的可见重心、真实字形墨迹或文字基线；文本Range矩形也不是字形墨迹轮廓。这些仍需像素与实际排版复核，不能伪造自动通过。

## 实际制作与修正顺序

1. 在现有计划和布局预算中写内容职责、第一焦点、信息组、四层间距、色彩角色和PC/手机重组决定；说明参考方法怎样服务本站，不以“高级”“现代”等词代替决定。
2. 用真实最短/最长内容试做，等待最终字体和客户端重绘；查看整页、相邻模块、连续卡片及末行。图片与文字各自的可见边界都要检查。
3. 在PC、手机、320px、中间宽度和实际断点两侧检查布局；按既有状态规则覆盖筛选/空态/复制/过期等实际分支。普通摘要的固定容量与首券全文边界继续分别执行。
4. 将问题写成“位置与视口 → 可见现象 → 对阅读/操作的影响 → 预期改善 → 复验方法”，集中修正原因及受影响调用页。不能仅放宽预算或用overflow隐藏失败。
5. 作者自检完成后交给独立角色。审核者先看真实页面记录第一印象，再看作者解释和测量；新候选按原流程复核。审美偏好与影响使用、层级、品牌或完整性的主要缺陷分别说明。

## 审核覆盖与证据

沿用现有 coverage / review 检查项，不增加自评分表。便携入口为每个已声明代表路由在PC和手机分别生成三类视觉项：

| 维度ID | 独立观察必须回答 |
| --- | --- |
| `page-composition-and-rhythm` | `focusAndOrder`：第一焦点与阅读顺序；`groupingAndSpace`：信息分组、四层节奏及空白用途；`alignmentAndBalance`：对齐对象/轴、文字基线、图片可见主体与文字组的光学平衡及跨端变化 |
| `palette-and-color-states` | `colorRolesAndBalance`：实际颜色角色、面积与主次；`readabilityAndStates`：文字可读性、已实测的对比度依据及适用状态区别，未测状态如实列出 |
| `imagery-and-brand-coherence` | `contentAndMediaFit`：实际内容与图像/图标是否匹配，无该类素材时说明事实；`brandAndCraft`：整页或授权区域的字体、比例、组件与操作语言是否连贯精细 |

每个已执行视觉项填写 `observations` 对象，键与上表一致，值为有位置和实际现象的观察；在现有 `evidence` 中列本候选真实证据，并用 `pixelEvidence` 指向其中的实际PNG/JPEG/WebP截图。PC和手机分别取证，可复用同次页面截图支持不同维度。检查器验证文件、格式、检查项和候选绑定，不能认证截图来源、观察真伪或审美判断是否正确；独立实看仍不可省略。几何JSON、CSS和作者解释不能替代像素证据。

这些视觉项补充既有全路由几何、状态与断点覆盖，不把1440/393两张截图当全状态实看。其他宽度、独特模板和状态按真实覆盖需求继续取证；缺证据为not-run。preserve只判断授权区域及受影响关系，范围外如实说明。图像来源和源图锐度不因本方法加入本排版专项；Logo显示大小、占位及对文字的影响仍按既有规则检查。

执行失败为fail，未执行为not-run；没有适用对象才可有依据地not-applicable。主要视觉失败仍需返工，不能被平均分、几何合格或其他维度通过抵消。规则接入和回归样例通过只证明方法及门禁工作，不证明未来站点的视觉完成度。

## 依据与采用边界

2026-10-22核对一手来源，以下为项目自有总结；离线任务采用本地冻结文本，不要求每次重新联网：

- [Atlassian Spacing](https://atlassian.design/foundations/spacing/)：关系分组、节奏、光学校正；不复制其间距数值。
- [Carbon 2x Grid](https://www.carbondesignsystem.com/building-blocks/foundations/2x-grid/overview)：容器、对齐轴、网格与断点；不固定本站列数、8px基础或padding。
- [Atlassian Typography](https://atlassian.design/foundations/typography/)与[Color](https://atlassian.design/foundations/color/)：字体角色和颜色角色、强调及状态；保留本站品牌表达和既有字号下限。
- [W3C Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)与[Text Spacing](https://www.w3.org/WAI/WCAG22/Understanding/text-spacing.html)：320 CSS px等价宽度下信息/功能保留，及用户覆盖文字间距后的容错；遵守二维内容和语言例外，不把测试值当默认行高或字距。
- [Impeccable Layout](https://github.com/pbakaus/impeccable/blob/main/.agents/skills/impeccable/reference/layout.md)：视觉判断与机械扫描分开；不导入其CLI或外观黑名单。
- [Anthropic frontend-design](https://github.com/anthropics/skills/blob/main/skills/frontend-design/SKILL.md)：基于真实内容形成连贯方向并批评渲染结果；不以某种字体、颜色或渐变的存在直接判失败。
