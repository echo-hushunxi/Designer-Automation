# Design methods adopted for Site V2

2026-10-22: [all-page visual completion](visual-completion.md) adds source-linked spacing, typography, color, responsive composition and independent pixel-evidence methods. It records the owner-confirmed distinction between purposeful space and empty gaps, and accepts polished familiar layouts with coherent brand identity. Its primary sources and adoption boundaries are listed in that local method; no external package was installed or copied.

Reviewed 2026-09-20; adapted on 2026-09-28 after actual renderer inspection and owner rejection, and verified against official upstream skill sources and GitHub API metadata on 2026-09-29. This is a project-owned adaptation, not a claim that complete packages or CLIs are installed. Normal generation reads the local adaptation; no live popularity lookup or global installation is required. The local skill is frozen with each new build; upstream updates require a deliberate compatibility review.

Use [creative craft](creative-craft.md) for the applied method. Versioned provenance is in `data/design-methods/2026-09-29.json`, included in the shared workflow response. At the recorded check, the selected design-focused packs were UI UX Pro Max (131,371 repository stars), Taste Skill (91,050) and Impeccable (72,278). Anthropic skills (178,896) and Vercel agent-skills (31,697) are multi-skill parent repositories; those totals must not be presented as the star count of one UI skill or compared as a global UI-skill ranking.

- [Anthropic frontend-design](https://github.com/anthropics/skills/blob/main/skills/frontend-design/SKILL.md): subject-specific visual decisions; plan, question generic defaults, implement and critique. Apply to layout and brand expression within the Coupon contract.
- [Impeccable](https://github.com/pbakaus/impeccable): separate product context from visual identity; distinguish design critique from technical audit and final polish. Use concrete visual criticism and an iterative repair loop. Its full CLI, hooks and detector bundle are not installed here.
- [UI UX Pro Max](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill): use its style, palette, typography and UX lookup approach as supporting research. Product keywords can retrieve irrelevant categories; inspect suggestions rather than treating them as required layouts. Its database is not vendored here.
- [Taste Skill](https://github.com/Leonxlnx/taste-skill/blob/ce26fc25c0e5e8cab638f883de62d9a86ee5e45b/skills/taste-skill/SKILL.md): infer audience and visual intent, compose actual imagery and usable action states, and plan mobile explicitly. Its preferred framework, dials, palette limits and blanket layout/style bans are not adopted.
- [Vercel web-design-guidelines](https://github.com/vercel-labs/agent-skills/blob/063bee94c3f4df8453406c830b0a7df0f2860278/skills/web-design-guidelines/SKILL.md): review usable semantics and real interaction states. Its linked interface guidelines informed the adaptation; they are not automatically fetched or substituted for SiteFly's frozen rules.
- Local Hallmark structure guidance (`~/.cursor/skills/hallmark/references/structure.md`): compare page shape and content rhythm separately from surface theme. The generation skill does not depend on that global path being installed; this principle is included locally.

The 2026-09-28 revision uses the local Hallmark entrypoint's separation of macrostructure, visual language and critique. Its prescribed theme rotations, typography-only preference, decorative catalogues, CSS stamps, required font pairings and local log writes are not adopted. A coupon destination needs its own task-driven composition and may appropriately be photographic, typographic, dense or spacious. The project-owned batch matrix and real-artifact comparison are the retained method.

Do not import fixed theme rotations, blanket font bans, root overflow clipping, decorative labels, obligatory animation or self-awarded aesthetic scores. They conflict with or unnecessarily narrow this project's requirements. No external skill can override explicit detail business constraints, readability, business semantics or a retained site's design. Those constraints do not freeze the same card markup, geometry or appearance across new sites. See the [owner's store/detail references](owner-card-references.md) for actual examples of distinct cards within similar shopping flows.
