# Coupon共同生成标准：Codex与Harness

用户于2026-10-13明确要求后续两种入口都采用本标准。适用于新优惠券站、明确复用与授权重做；维护只应用于改动范围及相关回归，保留历史冻结包。其他站型另定业务框架。最新用户要求优先。

## 所有页面的卡片密度与差异

追加读取[具体执行标准](card-density-and-diversity.md)，按[逐卡型计划](card-layout.template.json)记录职责、PC/手机分组、规格与摘要容量、短内容、主要对齐轴和真实差异。新绑定 `couponCraft.densityStandard` 冻结该标准和模板；从绑定显式路径读取，不依赖相对链接碰巧可用。新契约的 cardDecisions 增加这些必填决定，所有启用卡型都适用。计划只证明决定完整，不签发视觉通过。

首页同时读取[参考处理方法](home-card-reference-methods.md)，根据用途原创组合并分别验证PC、手机。最新用户确认的摘要容量与至少70×70商家Logo规则覆盖旧的全文自然撑高和较小Logo建议；历史冻结产物不改写。

## 先确定业务与真实内容

生成前读取[17类页面、模块和卡片字段框架](../../site-v2/references/coupon-site-framework.md)，冻结新Coupon公共库数据，写`docs/site-structure.json`。记录每类页面是否启用、模块用途、字段、数据绑定与空状态。有条件的节日/文章缺数据就按契约省略；不能为了凑栏目造内容。所有页面、搜索和客户端重绘消费同一快照。历史技能的示例US/USD数据默认不适用于新生成。

四参考共有12类已实看的用途，另5类是现有完整产品蓝图，不宣称四站都具备独立入口。排名/评分/产品评测需要额外真实数据与能力，本期无数据就省略，不能生成9.9分、虚构评价或收益承诺。完整对照与实测：[研究报告](../../../docs/COUPON-FOUR-REFERENCE-COMMON-STANDARDS-2026-10-13.md)、[观察记录](../../../engineering/reference-studies/coupon-four-20261013.json)。

## 生成前写具体设计决定

用绑定版本的`docs/site-craft.template.json`形成`docs/site-craft.json`，与结构计划一起preflight。模板空值不能过关；写实际颜色、像素起点、空间分配和变化原因，不能只写“高级、现代、参考优秀站”。这份计划不在站点前台展示。

- **颜色角色**：背景、表面、正文、辅助文字、主操作、促销、状态及交互状态。常规购物信息优先清晰可读，鲜明色承担重点；Banner、按钮、卡片与图标有共同关系。可以多色，也不强制所有CTA同色。不同页面用途的差异应有原因。
- **四层间距**：卡内分组、卡间、标题到卡组、模块间分别确定。店铺券卡本次实测10/20/24/12px，12–20px可作起稿参考，内边距10–20px；均非硬门禁。测量实际相邻边界，包含margin、伪元素、外伸CTA，避开广告占位。42px外伸箭头案例有构图原因，不能抄到普通券卡。
- **卡片按用途**：各类卡片记录Logo/图片、按用途选择的标题摘要与辅助字段和动作的空间预算、信息层级、主操作以及手机变体。促销卡、店铺券列表、详情主券、商家入口、分类/节日/文章不能统一套一个壳。未启用的卡片明确写原因。保留规定业务关系；Logo区/优惠信息/操作区可以采用熟悉分区，具体比例、分隔、日期位置、造型自由。
- **精选与操作层次**：精选组应体现主推和辅助优惠的角色，不能仅把普通列表卡片换背景色。分组、数量和具体构图自由，保留完整真实源数据、详情可达与同排对齐。浏览入口不能默认全部套满宽实心胶囊，先按用途确定轮廓、文字/图标关系、动作位置与视觉重量，避免按钮压过优惠内容。描边、开放式文字、票券边缘及实色重点操作都是可选方法，不强制全站同一构造。箭头是可选的视觉元素；完整实色按钮也可以成为明确的主操作，不强制两段箭头控件。先在实际页面核对按钮的显著性、文字对比度、点击区域和手机表现，不因造型有差异就判定有吸引力；不添加无证据的“热门”、销量或稀缺标签。
- **页面密度**：首页首两屏形成购物主视觉与可浏览优惠的节奏；店铺/详情支持连续比较与阅读。不要用巨大空白、同款卡墙或重复说明填满页面。Banner不重复已有全局搜索；只有实际独立搜索用途才增加搜索框。
- **跨端重组**：320px、常规手机与桌面分别决定内容优先级、列数、文字按钮/箭头及操作位置；依据实际父容器与长内容，不能只缩小桌面。主操作仍有明确可访问名称和足够点击区域。

一站内部设计语言一致，各站可以充分不同；本标准不固定字体、颜色、圆角、列数、Banner媒介或一套详情皮肤。保留新设计的实际原创比较与明确复用模式。

## 不能从参考复制的弱点

参考的11–12px日期、4.5px手机边距、小箭头、截断重要标题、裁剪Logo、广告空洞、广告解锁及不实统计都不是通过样例。继续遵守现行业务质量契约：券标题/商家名16–20px，其他允许文字通常≥14px，仅明确允许的内容描述采用其专门范围；Logo保持官方形状、完整条件可读、手机边距12–15px、实际操作满足点击/键盘要求。当前源技能中的固定业务尺寸与状态要求继续适用。

生成时提前检查：长短标题、不同Logo比例、无码/有码/过期/未知期限、空结果、末行推荐、过滤后重绘。不要靠裁剪、缩字、隐藏DOM或假数据完成布局。

并排券卡要检查卡内对应内容的对齐，不能只检查外框等高。同一视觉排内的商家身份、日期、标题起点、分隔线和主操作应遵循设计中确定的对齐关系；长商家名、长标题或日期换行要保持动作组清晰；不能为同时锁死所有文字、日期和按钮基线而制造大块空白。共享外框和主要对齐轴优先，内部文字自然成组。允许使用自然内容行、子网格或其他布局方法，不固定全站五行模板。手机重组后重新核对；摘要卡按已确认的行数及固定文字区域省略；完整详情保留全文，不缩字。实际检查长短内容相邻的整排卡片，并同时查看像素和对应边界。若用 CSS subgrid，共享轨道的元素不能叠加使子网格失效的布局 containment；必须确认最终计算样式和真实对齐结果。

用户于2026-10-14再次明确禁止首页券卡文字错位。对齐检查必须包含同一卡片类型、同一视觉排中商家名与优惠标题实际第一行的文字起点/基线，而非只比较容器边界；同时核对日期和按钮与实际内容的距离，短标题只保留约定容量内的合理对齐余量，包含长短内容、换列断点、字体加载与筛选/加载更多后的重绘。发现错位先修复，再报告完成。此要求不将不同板块统一成同款字号、卡高或按钮。

## 过期优惠的展示规则

用户于2026-10-14明确：过期优惠不出现在网站上。数据中保留原始记录供审计，但首页、店铺、全部优惠、节日、推荐和客户端重绘只展示未过期券；不生成 Expired offers 历史栏目。到期后移除整张券卡并更新计数/空态，不只禁用按钮或变灰。旧链接只展示不可用状态与当前店铺入口，不继续展示失效主券。旧冻结包保持历史版本。

## 语义和事实检查

`factChecks`记录实际检查方法：

1. 字段身份、动作文案与目的地一致；商家入口绑定SID，券入口绑定CID，分类入口确实进入分类。不能因URL含List误判页面用途；同一券的标题/商家/详情/复制作用域一致。
2. 数量明确countKind、范围与快照，区分商家数/券数/当前筛选数。隐藏模块和重复记录不计入可见覆盖。
3. 区分采集时间、发布日期、活动年份、到期时间和未知期限；采集成功不等于今天已验证，不能自动将活动改成当年。
4. Logo、商家、优惠和正文实体匹配；不要把同名其他公司的文章附到该商家。
5. 联系方式来自授权站点配置；订阅、评分、评测、广告等依赖有真实能力/数据才能出现，缺失时不编造。

## 自动审核与修复

### 详情主券与紧凑券行补充

主券、店铺券行和详情相关推荐使用 [细节生成技能](../../coupon-detail-generation/SKILL.md) 和 [细节审核技能](../../coupon-detail-review/SKILL.md)。原来的真实字段、16–20px标题/商家名、14px辅助信息、44px操作、Logo与模块底线继续执行。Couponur原始实测、采用值、手机重组、代码+按钮组合和四层间距分别记录。2026-10-20更新：普通摘要在PC和手机均按家族固定容量省略，保留完整源字段、可访问名称及正确详情；第一张券（主券、店铺首券）完整展示，不能省略。区域顺序及参考方法见详情技能；历史冻结包不改写。冻结文档移位时，以reviewContext提供的 `couponCraft.detailStandard` 明确资源路径为准。

### 文章图片

公共库文章的 `image_name` 与推荐项的 `image_name` 分别绑定封面和正文实体；在数据转换、首页文章卡、指南目录、正文和相关文章中保留这些关联。有可用真实封面时必须渲染，不能因为字段标为可选而在映射时丢弃。文件名不是完整图片地址，先核实授权静态资源来源与实际响应；空值或确实缺失的素材记录缺口，不使用错误实体的图片凑数。

先按实际桌面/手机容器测量图片的 CSS 宽高，再准备对应资源、比例和断点。核对真实图片格式与像素尺寸，不能只信文件后缀；不放大小图制造高清。原图不足时调整合理的图片区域或获取获授权的更高分辨率素材。封面构图、图文分栏、比例、边框和品牌关系自由设计；官方标志保持原色、原比例和 contain，不套用统一文章皮肤。

图片预留宽高或比例，按适用位置设置响应式 `srcset/sizes` 与加载策略。`sizes` 必须跟随真实 CSS 断点，尤其检查横排改为单列的边界；读取 `currentSrc`，按其文件实际像素核对渲染宽度和设备像素比，不把密度修正后的 `naturalWidth` 当成文件原始宽度。最终 ZIP 必须包含所有响应式候选文件并正确改写相对地址，不能只打包 `src` 中的回退图。实际打开解压后的文章目录、正文、相关文章及首页指南区，检查图片加载、选择的资源、渲染尺寸、裁切和手机重排；构建/链接通过不能替代这一步。

作者先实看桌面、手机与320px的实际代表页/状态；新方向先独立审核首页和必要内页，再扩展全站。审核者先看页面记录第一印象，再读取冻结计划、本标准与参考，审配色关系、卡片比例、四层节奏、密度、手机组织和事实语义。现有palette/density/card/brand/responsive/content评估记录这些实际观察，不另造自评分表。

数据/计划/数值校验是必要条件，不能证明审美通过。旧数值观察没有像素证据，不冒充正式receipt；后续实际审核需查看当次参考页面或有效截图。主要视觉缺陷或业务硬错误自动进入集中返工；最多3轮，单站自主生成预算2小时。耗尽保留结果与失败诊断，不能降标放行。最终目标是用户主动检查、沟通与Codex收尾合计≤60分钟，无人值守等待另计；以3个新站再累计10站验证，不能因接入标准就宣称已稳定达标。
