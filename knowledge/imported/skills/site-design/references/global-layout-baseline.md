# 全页面公共布局底线

版本：2026-10-23.6。来源：用户对首页、优惠详情及商店详情的容量、分类、晃动与横移纠正。本文件集中维护全页面容量与稳定性；页面专项只补充职责和例外，不能另写冲突规则。历史冻结包不追溯改写。

配合[全页面视觉完成度](visual-completion.md)判断整页焦点、空间节奏、字体层级、色彩和品牌协调。用户已确认清除无效空洞、保留有效留白；合理精细优先于猎奇。下列几何预算只验证声明的尺寸关系，不能替代这些独立像素判断。

## 生成前先解决容量

每个启用页面族及实际调用组件都要在布局预算中声明：内容容器、模块标题与内容边界、卡片集合、文字/Logo/动作槽、字号和四层间距。PC、手机分别选择预算，标出重组断点。先用真实最长/最短内容做一组，核对 `可用内宽 − Logo轨道 − 动作轨道 − 实际间隔`；不足时调整分组或列数，不能缩小70×70商家Logo、44px操作热区或既定可读字号。容量按下表中的用途决定，不能按第一项位置推定全文例外。

| 内容角色 | 容量与例外 |
| --- | --- |
| 普通优惠卡标题；推荐／目录／侧栏商家名称 | PC与手机均单行省略，实际标题盒等于一行行高；同家族同断点固定卡高。完整源字段、可访问名称及对应CID/SID详情保留 |
| 优惠详情主券 | 标题、商家、必要条件、日期与代码完整；无省略、遮罩或查看更多替代全文。需要时自然增高 |
| 商店详情身份卡 | 完整名称和真实全店券数；实际Logo100×100、卡高≤200px。下方所有券均为普通卡，首项不特殊化 |
| 分类／主题导航名称 | 完整可见，不省略、不截断、不限制行数；长名称自然换行，卡片随内容增高；上图下文的图标和文字同轴居中，左图右文的文字左对齐 |
| 文章、主视觉、正文及其他角色 | 按用途声明自己的容量，不继承普通优惠标题规则 |

单行必须作用到真正承载文字的内层，检查嵌套块的white-space、overflow和text-overflow；外层写ellipsis而内层硬裁仍失败。文字轨道使用确定的可用宽度，避免由max-content及整组居中让长短名称改变Logo、日期或动作位置。日期／数量紧随名称或标题，剩余空间放组外，不预留空白第二行。按完整组决定对齐轴，不给每个字段套统一大行高。

分类／主题必须含可辨识的语义图标与完整名称，按实际结构选择对齐：上图下文时，图标和文字都沿卡片水平中轴居中，文字槽及每行文字也居中；左图右文时，图标在固定图标轨道内居中、与完整文字组垂直居中，文字左对齐。名称不得继承普通优惠标题的单行省略或行数上限；优先按完整单词自然换行，极长连续字段才断词。按最长名称调整内距、列数和自然高度，不缩字号掩盖容量不足。二者紧凑成组，间距在本站预算内（最大20px）；去掉被取消标识及其空轨道。不把两个字段拉成空旷长条，也不为差异强迫八站同一布局。图标颜色、实际尺寸与长分类名的视觉判断继续按页面专项。

分类图标按站点设计：同站统一造型、笔画与填充语言，跨站采用符合各自品牌的图标形态，不能把同一套SVG路径换颜色、底座或站名反复复用。同站不同分类应有准确且可区分的图案，例如配饰用眼镜或腕表、珠宝用戒指或宝石，不能一律套钻石。作者在本站设计决定中记录图标语言、名称到图案的映射、实际尺寸、颜色、来源及许可证，并使用本地冻结资源；未知分类显式报告缺映射，不静默回落到通用星形、标签或礼盒。审核横向对照同一分类在各站的真实像素，同时检查单站完整分类集合。路径指纹、家族名称与几何预算仅作复用诊断，不能单独证明风格差异或语义正确。

首次实现后先在实际浏览器验证这一组的PC/手机与窄屏，再扩展同组件调用页。这是作者制作步骤，不增加用户批准环节。后续仍检查宿主宽度、标题到首卡、模块累计间距，不能用组件单测替代页面。

手机不是单一393px样本：必须从实际CSS/组件行为确认重组点，而不是按习惯假定700px。检查断点两侧与中间宽手机段的最短、最长标题；旧多行min-height不得继续制造空带。按可用宽度重新编组或换列，不通过缩Logo、缩热区或把所有站改成同一券行解决。


优惠摘要的省略不能切断一个关键事实：折扣、价格、币种、计费周期及门槛数值应作为完整单元优先可见。例如DoorDash源门槛$25+若在320px显示成“$2...”仍然失败，保留原始DOM/详情并不能挽救错误首印象；将摘要重排为“35% off $25+ orders”，源限制继续保留在摘要后部、完整可访问名称及详情中。同样不能让Free、Up to、iPhone App等决定优惠理解的字段被前面的套话挤没。作者和独立审核在最窄端记录原文、可见摘要及实际像素。

## 布局稳定性：实现与验收

1. 字体、图片和图标加载前预留最终空间，Logo及动作轨道不由文字固有宽度决定；同一视口在短长文字、重绘、加载与反馈前后不改变普通卡和字段槽位。用同一CID/SID/分类ID对账，不能用数组位置冒充身份。
2. hover、focus、pressed使用颜色、背景、描边颜色或不占布局的阴影；卡片、文字组和邻卡不位移、不缩放。边框宽度预留一致，禁止hover后才增加border/padding、改变字体粗细造成轨道变化或translate移动内容。减少动态设置下仍可辨认焦点。
3. 筛选后整页不能因滚动条出现／消失横移，必要时在正确滚动容器预留scrollbar-gutter。合法的结果重排只改变结果顺序，存活实体的卡片容量与内部字段槽仍稳定；根页面不得横向溢出。主动打开面板、全文主券增长等有意变化分别声明，不能借此豁免普通卡漂移。
4. 修复所属组件的布局责任，清理旧grid-area、隐式行列、min-height和Flex收缩冲突。禁止不断叠加!important、nth-child、逐卡translate来校正。共享组件同时检查首页、优惠详情、商店详情及其他真实调用页；两类详情的共同修正同轮生效。
5. 作者与审核分别执行初始／字体图片完成、短长内容、hover进出、键盘focus、按下、减少动态、筛选／搜索重绘及滚动条有无。320/393/1440及实际断点±1覆盖；未执行留not-run。读取了规范或连续两帧稳定都不能代替这些状态证据。

公共检查器的summary检查单行省略、内层文字与同家族高度；topic检查图标方向、名称左对齐与间距；stability按实体与字段槽比较快照，默认容差0.75px且不得超过1px。旧失败保留；不能通过不断重置基线把漂移洗成通过。机器结果只证明已执行范围的几何，不证明审美。

## 所有页面必查

| 检查 | 测什么 | 如何判断 |
| --- | --- | --- |
| 内容不贴边 | 内容盒与视口左右距离，手机安全区域，首尾卡/按钮可见边界 | 必须有可见内缩；满幅背景允许，但文字及操作仍需内缩。不能用隐藏横滚掩盖越界 |
| 顶部与阅读轴对齐 | header内容、页面主内容、模块标题和网格的实际边界；约定同顶的主侧模块 | 按本站声明轴测偏差。品牌Logo内部天然留白不等于盒错位；有意错落须有阅读目的，不强迫所有模块齐顶齐底 |
| 图文轴与视觉平衡 | 图片槽/实际图片、声明的完整文字组、可见图形与字形、同排文字基线及操作组合 | 先选择同顶/中心/基线关系，再测实际轴；盒中心不等于可见重心。光学校正须有依据且不破坏热区；长标题与跨端重组后复查，不能一律居中或五五分 |
| 卡间隔 | 同行相邻卡、换行、连续列表的真实边界距离 | 独立卡不能相碰；连体列表可共边但须有内部留白/分隔。不得仅检查CSS gap，margin/padding叠加后重新测 |
| 四层间距 | 卡内部、卡与卡、标题到第一张卡、模块到模块 | 分层记录。约24px以上无语义空带或大于组间距两倍触发实看，不自动压缩主视觉/正文阅读区 |
| 高宽与文字容量 | 各用途在当前断点的实际宽高、文字轨道、行数、字号/行高 | 同用途遵循本站预算，长摘要不撑卡；优惠详情主券全文例外。字太大导致有效优惠/门槛无法读懂需重组，不能只因无横滚放行 |
| 图文/动作边界 | Logo包装、图片本体、可见字形、日期、按钮和装饰层 | 文字不进入Logo轨道，按钮不覆盖文字，装饰不挤占或遮挡目标。最短/最长及末行都看 |
| 连续页面与状态 | 实际产物路由清单、加载后、筛选/搜索重绘、空态 | 隐藏节点不算已显示模块；零数据须审核空态。遗漏页面或未执行状态保留not-run |

## 起稿参考，不是统一皮肤

普通内容可从手机12–16px/PC24–40px页侧安全距离、卡间10–20px、标题到内容12–20px、模块间24–40px开始试排；卡内分组常用8–16px。它们是起稿 target，本站应依用途选择并写明预算；已存在的更具体硬规则优先。文章阅读、主视觉、连体列表及故意错落可以有不同预算。不要给全站h1统一字号，不固定所有站列数、卡片高度、边框造型或动作位置。

真实测量观察（2026-10-21；不是要求）：Couponur H-PROOF商家页手机393/320内容左右各14px，Similar Stores连续卡实际间距12px；PC券行126px高、Logo/信息/动作分轨，标题20px/27px行高，手机改16px/20px并重新分组。Couponister首页手机左右12px，推荐区双列gap12px，PC采用更宽容器和更多列，不能机械缩放PC。参考也有局限：部分Logo低于既定70px，PC主视觉实测约488px，均不能覆盖用户Logo下限和Banner PC480/手机400px上限。Dealmerica指定URL本次返回404，未提炼其尺寸。不要复制参考缺陷。

## 可执行检查与覆盖

复用 `../../site-design-review/scripts/inspect-layout.mjs`，通过options的 `checks` 绑定实际DOM，而非规定DOM结构。支持viewport宽度范围、gutter、box、typography、alignment、distance、grid、separation、summary、topic、stability、packing、image-fit、action-shape。区间由本站冻结预算提供；选择器缺失、隐藏、样本数量不符均报告，不空集合通过。无预算是not-run，几何符合只记measured，无视觉通过含义。

alignment的axis可选left/right/top/bottom/center-x/center-y，分别比较边缘或几何中心。例如图片与声明的信息组用`{type:'alignment',selector:'.merchant-image',with:'.merchant-info',axis:'center-y',range:[0,0]}`；这是居中方案的语法示例，不是所有卡片必须居中。长文字方案可选择top，对齐范围也可容纳有理由的局部光学校正。测量仍限元素盒；真实文字基线、透明图像主体和光学重心按视觉完成度专项独立实看。

每个工程以最终产物完整routes对账，区分内容页、跳转页和未知页；所有启用页面PC和手机执行基础几何。每种独特模板、卡型、短长数据、状态和重组断点±1进行实际像素检查。代表样本必须注明覆盖范围，不能把机器遍历称逐页实看，不能只检查首页/两个详情就声称全站通过。

新候选回执绑定build/hash、路由、视口、预算和检查器版本。尺寸失败、缺必需映射、隐藏必需模块或主要视觉失败均不可放行。复核先看像素，再读预算；作者集中修复问题包。预算变更必须说明设计原因并留存原失败，不能仅放宽数值消除错误。既有冻结候选保持原版本。

### Harness冻结预算格式

新绑定在 `docs/site-craft.json.layoutBudget.pages` 按 `site-structure.json` 的已启用page.id配置。每项包含 `id`、`routePattern`（相对产物路径，仅`*`通配）和`checks`。例如阅读轴 `{id:'heading-axis',type:'alignment',selector:'.section-title',with:'.section-grid',axis:'left',range:[0,0]}`；集合间距 `{id:'offers-gap',moduleId:'related-offers',type:'grid',selector:'.offers',items:'.offer',horizontalGap:[12,18],verticalGap:[10,16],height:[104,104]}`。示例值仅演示语法，不能复制为所有卡高度。

每页必须有非optional的gutter、alignment、distance，320/393/1440都适用。每个含卡片的业务moduleId还需box或grid与typography（含真实文字轨道）映射。新绑定的普通优惠／商家模块另需summary，分类需topic，三类模块均需stability，均非optional并覆盖320/393/1440。可使用minViewport/maxViewport分预算。预算哈希与检查器随build冻结；原生浏览器回执自动执行，新候选在handoff/独立审核时核对。完整新站以实际HTML清单验证PC/手机，非内容根跳转单列；preserve只验证授权调用范围，不能据此声称整站通过。已有绑定不追溯升级。

普通优惠／商家摘要模块必须给出卡片高度区间与文字`maxLines:1`，typography同时给出fontSize、lineHeight和width；优惠详情主券全文及分类／主题名称不套摘要高度/行数上限。分类仍需文字宽度、字号、行高、间距与topic/stability映射；topic检查完整文字、祖先裁切及结构对应的对齐：上下结构图标和文字同轴居中，左右结构文字左对齐。卡宽与文字宽不是同一个值。一次性填一个超大范围不是设计决定，独立审核仍需对照短长真实内容。图文分离检查同时测元素盒和被合法overflow裁切后的可见字形。

外框不是唯一阅读轴：侧栏容器带padding时，应测实际标题/卡片边缘；不要为了外框数值相同破坏可见对齐。紧凑网格重组后也必须检查其父容器底部，防止列数变化而外框保留旧高度。未匹配、透明或隐藏元素不能充当覆盖。

stability格式：`{id:"offer-stability",moduleId:"offers",type:"stability",selector:".offer",keyAttribute:"data-cid",fields:[".logo",".copy",".action"],tolerancePx:0.75}`。返回stabilitySnapshots，后续同视口实测把首次快照传入options.stabilityBaseline；缺基线或没有可比较实体是not-run。原生浏览器保留同会话同路由／视口的首次基线，执行连续两帧和后续回执比较；冻结旧检查器行为保持不变。

状态能力边界：公共预算不能自动从冻结数据推导所有空态、无效态及筛选分支，也不自动遍历hover／键盘／加载状态。遇到这些状态必须保持失败或not-run，按现有页面状态规则用冻结数据对照真实操作并独立复核；禁止把必需选择器设为optional或以DOM当前集合反推期望来消除失败。状态合同接入并验证前，不宣称便携包已实现所有页面所有状态的自动验收。

按钮文字也有独立容量：按最终加载字体核对“标签字形宽度＋图标＋间隙＋左右内距”，再决定按钮宽度和断点。44px热区合格不代表标签排版正确；预期单行的短操作不能意外拆成两行或贴住图标。换展示/正文字体后重新实看主按钮及最窄状态，不能沿用旧字体下的宽度结论。确需多行的操作另行设计文字区和热区，不以全局强制nowrap掩盖容器问题。

## 商家卡：对齐必须落实到字段和可见文字

2026-10-22 Paloma 负例：优惠详情／店铺详情左侧末组16张商家卡，Logo与名称跨满整行，券数却只占箭头左边一列。44px箭头加8px列距让券数中轴左偏26px；卡片尺寸、Logo下限和页面无横滚均通过，仍然错位。修复前 build b-ca0f47e4-de88-4013-8f76-8ca6442bb2b3，修复后 b-b051f8b2-8736-4e63-bf93-3142de7593cb；两类详情在PC／手机／320px的本轮测量与独立像素是该案例依据，不表示其他页面自动通过。

- 作者在每个商家卡家族的PC／手机预算中明确对齐对象、轴与作用字段。采用Logo／名称／券数上下居中时，三者按同一水平中轴核对；横排Logo＋名称券数组时，按整组的垂直中轴核对。其他有用途的构图声明自己的关系，不强制所有站使用上下卡。
- 数量及其单位不能因右侧按钮、箭头、空Grid列、父包装或旧grid-area而偏移。普通名称固定单行省略，名称与券数自然相邻；不要靠固定空行或逐卡translate补丁修复。
- 同时核对字段盒与数字／单位的可见文字行。外层100%宽并居中，里面的flex-start、text-align或嵌套span仍可偏移。可用Range的实际可见文字矩形检查排版；它不识别字形墨迹或Logo光学重心，仍须正常像素复核。

## 容量驱动的修复与生成（2026-10-23）

先判断当前内容和操作是否成立，再选重组方式。按宿主实际内宽、卡片最小可读宽度和真实字段计算列数；不能把设备名当断点，也不能从单列直接跳到固定多列。15–30px可作为紧凑网格列距起点，本站按用途定预算。外层换列后，内层嵌套网格也要重新测。能放多项却只剩巨大单项、文字只余“Booki…”等不可辨片段，均需改列数、文字轨道或卡内组织；合法ellipsis和无横滚不是放行理由。可见字符预算只是筛查，审核仍判断商家/优惠是否可辨，短名称如H&M不为凑字符数扩写。

空间足够时优先增加每行项数，保持卡内Logo、文字和操作的正常间距；不能仍保留两项，再用放大padding、空轨道或space-between把内容拉开。卡片内距与网格列距分别设预算，容器变宽首先调整列数。移动端按钮挤占正文时，主动选择紧凑可辨动作（保留可访问名称）、整卡入口、或单独完整操作行；先保持正文、Logo和热区底线，再验证动作归属，不把桌面宽按钮硬塞进窄文字列。分列后剩单项也须按任务重排内部内容，不拉出空旷卡壳。

文章摄影默认保留原图比例；明确采用横排等高构图时，图框与完整文字组（标题＋阅读入口）顶边和底边一致，照片用object-fit:cover等比裁切填满规则图框，加载前预留最终尺寸。声明fitMode:cover并检查真实objectFit，禁止拉伸、空框或仅把小图居中。纵排卡保留其比例，不强套横排规则。整卡链接内装饰Read提示不设独立44px热区；真实独立阅读链接仍至少44px。不同职责模块须各有标题、边界与间距；不能为了填满横排把节日与文章混成同一模块。面包屑等低优先信息按内容高度和当前首屏有效内容分配内距，不照搬桌面空白。

主操作使用一眼可识别的常规矩形或正常圆角轮廓；卡壳票口、品牌装饰可以保留，不能让可点击按钮像异形标签。无码提示是状态文字，不能做成另一个巨大假按钮。横向Logo＋名称/数量的信息组，组内文字默认左对齐；普通卡片说明、分类、名称、数量默认无衬线，展示标题可保留品牌字体。上下居中卡型仍按同轴关系审核，不能把左对齐规则强加于所有构图。

实施只改有问题的所属组件，先列出需保留的已正确模块、图片比例、品牌、真实ID和行为。清除冲突级联的根因，跨页面共享调用同步复验；不使用运行时JS重排，不靠叠加!important、逐卡定位或固定设备尺寸补洞。修复后比较好样本、失败样本、最短/最长/末行与实际重绘状态，检查没有把原来好的改坏。
