# 首页卡片：学习处理方法，形成本站设计

版本 2026-10-23.3。依据用户四张首页参考截图和随后明确确认的设计目标。适用于首页卡片生成与审核；跨页复用时按模块用途应用，不授权重做范围外页面。引用截图是观察材料，不能从缩放截图推导 CSS 硬尺寸。用户已明确要求原创组合，不能进入 reference-rebuild 或照抄参考皮肤。

## 先确定容量，再组织空间

用户确认的共同限制：

- **卡片家族**以“本站＋相同模块用途”定义；同家族同断点使用一致的规格、文字区域及操作规则。不同用途、不同站点可有不同构图和尺寸。
- 每家族在实现前声明卡宽范围／最大宽、常态卡高／最大高、Logo 尺寸、标题／商家／描述的行数与行高、按钮区域及四层间距。在可用容器内响应收缩，不用全设备固定宽度造成溢出。
- **摘要卡可选择字段并截断**。普通券、推荐券、店铺浏览券的优惠标题和普通商家名称均单行省略；保留完整原始数据、可访问名称及同一 CID 的全文详情。不能把 `Up to`、门槛、币种等删改成错误优惠；重要优惠在摘要中仍须能被理解。不要截断实际优惠码、错误反馈或用户需要阅读的完整详情正文。
- 真实的优惠类型、目的地、状态仍决定操作。日期／商家／描述／标签是否显示按模块用途记录；不要求每张摘要卡展示字段全集。选择真实标签时先明确它帮助用户判断什么，不添加假紧迫、热度或验证。
- **全部商家 Logo 展示区至少 70×70 CSS px，PC 和手机均适用**。实际图片区域满足下限，外框、网格槽、点击热区不能代替。保持比例和完整标志；合理上限由卡片用途和空间预算确定，不能放大 Logo 把正文或按钮挤散。本专项不处理素材分辨率与清晰度。
- Banner 整个展示区域 PC 不超过480px、手机不超过400px；这是上限。

固定文字区为整组建立可预测容量，允许短标题留下合理余量。检查的是整组比例与最长空带；不能为预防所有极端内容而把每张卡预留成大空壳。内容过长依次选择：语义完整的摘要、规定行数省略、减少列数、调整分组／断点。调整规格应作用于整家族，不能单张无限撑高或把字号缩到约定底线以下。

原 `naturalGrowth` 计划字段兼容保留，用它说明“摘要受容量限制／完整详情自然增长”的边界，不再强制所有摘要卡全文撑高。未授权的历史冻结项目保持旧契约。

## 焦点与空间关系要落实到页面

优惠卡通常以优惠价值为第一焦点、操作为下一焦点，商家和日期辅助判断；商家发现卡以品牌身份为焦点。用字号、字重、位置、面积、适量强调色共同组织，避免每行同粗同重，也避免标题、标签和按钮互相争夺。橙／红等颜色可结合品牌使用，标签只有真实且有判断价值时才加入。

同一信息组内距离应小于组间距离；操作紧邻它的作用对象。分别定义卡内分组、卡间、标题到卡组、模块间距，看真实边界而非只读 `gap`。对齐选择主要阅读轴与动作轴，不强行锁死每个字段导致内容被拉散。字体和正文颜色沿用本站语言，构图差异必须在去掉装饰与换色后仍能看出来。

2026-10-23 用户补充：手机券行若采用「左 Logo、右侧标题和日期」的横向构图，领取按钮应靠卡片右侧的稳定操作轴；可在文字下方同右边界排列，不跟随短文字停在左边。实际看同组短/长券与末行的右边界、点击区和阅读宽度，不用缩小 Logo 或挤窄标题换取独立按钮列。此条件不要求其他品牌或不同用途都改成这套构图。

## 手机是同一设计的重新组织

四张参考是 PC 截图，不提供已验证的手机版。生成者针对本站每种用途，先确定手机焦点、阅读顺序、字段容量、Logo 与文字及动作的位置，再实现响应式。手机可以重组分区、调整列数、精选层级和可选字段，保持数据含义及正确入口。

70px Logo、可读标题及44px实际操作区域同时成立；不让全部站点在手机自动退化为同一左图右字加底部日期按钮。也不为追求不同把 Logo 放大、正文挤成窄柱、动作移离优惠。使用真实短长内容检查320px、常见手机、PC及实际换列点两侧，核对动态渲染与静态一致。

## 生成与审核采用同一组观察

在现有 `docs/card-layout.json` 为每种用途记录：需要用户作出的选择、采用的参考处理方法、本站的转化理由、跨端规格和文字容量、真实样本与详情入口。不新增审批流程，不通过填写模板代替设计。

作者及独立审核分别检查：

1. 首先看到什么，能否立即理解优惠／品牌，下一步操作是否清楚。
2. 同组最短／最长标题、长商家名是否保持规格；截断可辨认且全文详情确实可达。
3. Logo 最终图片区、文字区、按钮区有无挤压、越界、错位、异常空洞；整组密度及末行是否成立。
4. 同站不同用途是否服务各自任务；同批同用途 PC／手机分别并排，信息分组和操作关系是否有实质区别。
5. 日期／标签／按钮的真实含义、点击与键盘、筛选／加载后的样式和数据是否正确。

尺寸检查、视觉判断、行为检查分开记录。既要符合容量和可读性，也要真正改善页面的重点、比例、密度和跨端构图。数字通过、DOM 不同、换色、读取了参考或计划齐全均不能单独判定合格。

### 实现后的容量核对

不能只检查新写的 CSS。读取最终计算样式与实际边界，核对 `height/min-height/max-height`、行高、行数、Grid 行列位置和 Flex 收缩。旧断点、选择器优先级、日期的双行最小高度及遗留 `grid-row` 都可能使声明与结果不同。卡片外框没有横向溢出，也不代表内部按钮、底边距或文字容量正确。

每次改变卡片结构，必须用最短和最长实际标题、最长商家名分别检查：按钮到卡片边界仍有预算内距；文字与操作不相交；短卡没有无意义空带；动态重绘采用同一套布局。除常用手机与桌面外，检查实际媒体查询切换点两侧；发现旧布局坐标继续作用时，在当前卡片作用域内统一清理或重设，不叠加单卡补丁。

断点内也有容量边界：普通标题／商家名执行单行容量，清除旧多行最小高度，按整个宽度区间调整分组或换列，保持家族规格。摘要不能先浪费空间重复商家名和套话，再把实际折扣截掉；保留真实完整源数据及详情，检查最窄状态的优惠仍可理解。

### 首页维护先隔离旧定位，再检查整页

2026-10-21 三站首页维护的实测纠正：新卡片继承旧组件类时，旧 `grid-row:span N`、`subgrid`、显式网格位置、`min-height` 或带页面选择器的轨道声明可能继续生效。新 CSS 写了正确尺寸仍会出现图文错位、动作落到框外及隐式空行。制作阶段先列出复用类及其布局责任：保留必要行为/数据钩子，新卡型使用自己的布局作用域；不需要的旧定位在家族层清理，不逐卡补丁，也不靠更大的外框容纳错误位置。验证最终计算样式及全部子区域边界，覆盖商家、分类、指南等模块，不只测首组券卡。

页头、Banner、栏目标题和首列卡片共用本站声明的阅读轴。检查嵌套容器有没有重复收窄，尤其手机主容器已经有页边距时，内部不再无意减去同一边距。分类长名称造成的可见字形越界可能增加根页面宽度，即使元素外框都在屏幕内；实际读最长分类名，按可用宽度重组图标/名称/数量或换列，保留完整可访问名称及正确导航、不缩字，也不在根节点隐藏溢出。

模块差异必须覆盖商家发现和主题导航：不能券卡已经不同，却让所有手机商家区再次退化为同款“居中 Logo＋名称＋数量”。按本站任务选择品牌架、紧凑身份组、名称主导或其他合理组织；这些是可选方法，不是轮换模板。若选择内部横向品牌架，声明边界、真实可达的全部商家及触摸/键盘方式，验证末项可见、焦点不裁切且不传播为整页横向滚动。

### 参考研究必须形成画面上的决定

后续首页方向制作与审核追加执行[首页视觉校准](cases/owner-home-visual-calibration-20261022.md)：保留醒目主视觉、整页色彩角色、精致页头、按钮层级与可识别分类的完成度，跨站重新设计构图；不要把已认可画面的配色、商品组合或卡片几何变成统一模板。图稿认可、实际网页审核与发布分别记录。

“更好看、去同化”的重做不能以“换了展示字体、大字口号和彩色矩形”作为方向成立的证据。先实际观察参考的购物入口、视觉主体、文字/主体的比例、主次信息与模块密度如何衔接，再用本站真实商家、优惠和任务形成一个清楚的构图决定。图片、数据主券、图文编排或纯文字结构都可选；不规定必须有图片，也不规定固定的主视觉或卡片模板。参考只转化为本站允许的内容角色，共用禁止清单中的装饰眉题不能作为“设计感”手段；自定义 class 也不能绕过内容意图审核。装饰不能冒充优惠事实，不新增无来源的热度、排名、倒计时或可信度。

独立方向审核先看真实 PC/手机首两屏，写下第一焦点、购物动作及模块衔接，再读作者方案；若画面仍是被用户否决的通用结构，清洁度和几何合格不能使其放行。已有用户否决是负面样本，不能沿用那版的历史 pass 作为审美依据。

手机要保留这个构图决定的有效关系：可以改变图片裁切、图文顺序、字号节奏和动作组织，但不能把有意义的主体整张漂白成背景，也不能为了保留 PC 的列数让 Logo 与动作相撞。预先算清最窄卡片的内容宽度：至少包含真实 Logo、动作、间隙和内距的预算；不够就重组或换列。短标题的日期紧随阅读组，不为最长标题预留一条空带再把日期/按钮推远。实际断点两侧和宽手机状态分别检验，同一颜色和字号下仍应看得出各站的构图关系。

容量和稳定性唯一维护于[全页面公共布局底线](global-layout-baseline.md)：普通优惠标题／商家名称单行省略，分类图标左侧或上方，上下结构同轴居中、左右结构文字左对齐；使用summary／topic／stability和真实状态证据。首页与详情的共享调用同步检查，视觉差异仍逐端独立判断。

窄屏语义反例：Rally Halloween 的源标题“Download the Free iPhone App”在320px省略为“Download the Free...”时，优惠对象消失，即使单行和尺寸正确也不通过。首页摘要可写真实等义的“Free iPhone app”；完整源标题、可访问名称、CID和全文详情必须保留。按最窄端的实际字形重新审核，不靠字符串长度猜容量。
