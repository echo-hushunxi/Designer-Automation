## 用户确认的详情编排边界

主券的身份、完整优惠信息与代码／领取动作必须构成一个统一视觉区域，不能用独立底色、分割边框或空带拆成两块面板。图文与动作可按本站品牌在统一区域内组合；不强制八站同一结构。普通券日期紧跟标题，动作靠近对应内容。共同卡片修正同时覆盖优惠详情与商店详情，商店身份不伪装成单券领取区。

- PC 双栏的辅助侧栏实际外框宽度不得超过300 CSS px，内部布局须依据其扣除padding后的真实宽度设计。手机改为单列内容流后按可用宽度排版，不为保留PC侧栏宽度再造两侧空带。
- 左主区域从主券底到关联区标题／广告位的间隔：真实有广告时只保留20px，不放空广告占位；没有广告按同样紧凑关系组织。后续完整模块边到边间距在30／40／50px中按用途选择，不能叠加父padding和子margin扩大空洞。标题到首卡、卡内和卡间距离分别预算，不统一改成30–50px。
- 右侧分类／主题不展示Picked、Featured、推荐主题等附加推荐标识，也不保留其空行、独立网格轨道或特殊选中外框；名称、语义图标和真实导航保留。去掉标签不代表所有站重画同一分类皮肤。
- 两类详情采用同站一致的紧凑页头：搜索框的可见底板明显低于header，在上下保留可见边距；输入、提交、展开、Esc、焦点与至少44px实际操作热区同时可用。不能把50px紧凑header中的搜索底板做成近乎满高，也不能靠收窄礼物／导航入口让搜索占满。
- 手机只使用一层既有页面左右边距，不再给主区域、列表宿主和嵌套包装叠加外层左右padding；保留卡片内部必要的文字边界。图像、商家名、标题与日期建立可解释的共同阅读轴；商家名不得锁在Logo下方窄列而出现单字孤行。
- 带背景／边框的面板有自己的内部留白，不能因它也是列表宿主就清零左右padding；核对面板标题、首末卡和末尾链接到内边框的实际距离。独立圆角卡必须有可见卡间距，不能上下贴合成连续白块。单列和多列均测实际边到边距离；不要拿多列网格的DOM相邻元素纵坐标差当作行距。连续列表只有明确采用共同外框、分隔线和连续行构图时才允许零间距，不能用来解释已经分离造型的卡片。
- 逐工程、两种详情、PC与手机实看：主券统一视觉区域、标题日期归组、实际模块间距、侧栏外框和内部容量、无推荐标识、搜索底板上下距离及嵌套左右边距。包含有效／不可用、短／长商家、短／长标题和重绘；外框齐平不代表图文字形平衡。

本节是明确用户要求。后文历史起稿目标与其冲突时以本节为准；旧冻结构建不回写。

## 必要区域

优惠券详情 PC：

```text
左侧主区域                    右侧辅助区域
1. 对应优惠券领取／复制区      1. 推荐主题
2. 推荐优惠券                2. 推荐商店
3. 推荐商店
```

左侧三个模块属于同一个主区域，不能把第三个移成横跨两栏的尾区来消除列高差。右侧主题先于商店。无码券在第一模块提供真实 SHOP NOW；失效旧链接在原主券位置给不可用提示和正确商家入口，不显示失效领取操作。推荐区继续检查。

手机空间不足时将两栏变为单列，沿用既有阅读顺序：领取区 → 推荐优惠券 → 主区域推荐商店 → 推荐主题 → 辅助区域独有推荐商店。不得用横向溢出硬保留 PC 双栏，也不得把侧栏插到领取区与推荐券之间。断点取决于实际内容可容纳宽度，不按参考截图反推固定断点。

2026-10-22 用户附图最终明确：商家详情顶部是一张设计完整的商家卡，包含实际100×100 CSS px Logo、完整商家名称、真实优惠券数量，总高不超过200px。风格自由，各站依品牌选择边框、纸票、柔和底色、图文位置及数量处理；附图用于说明信息关系，不把附图皮肤固定成唯一模板。下面紧接优惠券列表，已有功能性筛选可保留。保留原始名称、Logo及数量节点、SID和更新钩子，不硬编码或用筛选后已显示数量替代全店数量。零券、单券与多券采用真实状态。不能把商家卡误删、退化成纯文字标题，面包屑和券内身份不能替代它。PC、手机、长名称及数量单位均不得裁切或越卡；100px图片下限与200px总高度同时满足。页面其他模块、优惠券详情主券完整要求和既有导航保留。

侧栏分类按公共布局规则：语义图标在名称左侧或上方；上下结构图标与文字同轴居中，左右结构文字左对齐，紧凑成组；商家Logo与实际名称组按本站声明轴对齐。清除旧推荐标签、空列和固定两行名称轨道。标题长短不得令整组横移，外层center不能替代实际字段检查。

两种详情页的主区域推荐真实去重商家至少16个，推荐主题至少8个。辅助商家保留既有范围，不能把左右合计当作主区域16家，也不额外发明侧栏统一16家的要求。手机去掉主区域已经出现的重复商家目的地，独有商家保留；不得据此减少主区域16家。真实数据不足报告缺口，不造店铺凑数。

## 卡片容量

“固定”指同站、同用途、同视口规则下预先确定规格；不同站、不同用途、PC与手机可以各自设计。宽度可以随容器和列数响应式计算，但须有最大宽度和明确计算方式，不能由文本决定。高度在对应卡型／断点固定，字段区域先分配宽度、行数和行高。

普通优惠标题与商家名称的单行容量、实际内层省略、日期紧随、无空第二行和稳定轨道统一见[全页面公共布局底线](../../site-design/references/global-layout-baseline.md)。只有优惠详情主券及商店身份卡按完整内容规则处理。

下面的推荐券、普通店铺券、推荐商家及辅助商家遵守固定容量；不能因为标题、商家名或日期更长就单张撑高。短内容保留合理对齐余量，不能把所有卡拉高去迁就最长样本。先决定字段取舍、构图、合理容量，再处理省略。

**优惠详情主券完整展示是明确例外。** 优惠详情顶部主券的商家名、优惠标题、必要条件、日期／状态及操作完整可见，不使用省略号、line-clamp、遮罩或“查看更多”代替完整首券。先按真实内容安排紧凑布局和高度预算；极端长内容放不下时，完整展示优先于固定卡高，只允许首券适应内容，不能把此例外扩散到推荐列表。

- 超出文字槽的标题、商家名、辅助描述可以省略；原始字段、正确 CID/SID 和完整可访问名称保留。可选字段按模块用途省去，不保留空轨道。
- 同商家推荐区不逐卡重复显示当前商家名：从真实商家 ID／店铺链接核对归属，保留 Logo、优惠标题、日期和操作，并重新收紧文字组；不要只隐藏文字而保留其行高。混合推荐中其他商家的身份仍须可辨识。该取舍仅适用于普通推荐券，主券及推荐商店的身份保持完整。
- 摘要进入对应完整详情，不能只依赖鼠标 title 提示。首券不能通过额外点击才能看到完整标题来冒充完整展示。
- “隐藏多余展示文字”不等于丢弃原始数据或复制省略码。领取操作、真实状态、反馈与实际优惠码不能因卡片裁切而丢失。揭示后的长码自然换行完整展示、复制完整原码；复制前仍掩码、刷新复位。
- 首券保留原有领取规范。有码主操作使用复制图标和明确的 Reveal & copy／Copy 文案，不能用导航箭头代替复制／领取图标；点击成功反馈与复制状态一致。无码主券保持真实购物操作及对应购物语义，不能为了图标一致伪装成复制。推荐导航可用箭头，不将导航规则套到主券。
- 卡片标题／商家名16–20px，辅助文字至少14px，真实动作至少44×44。商家实际图片展示区在PC／手机均至少70×70；84px仅是历史起稿目标，不是统一构图模板。
- 不使用整卡或页面根节点 overflow:hidden 掩盖按钮、Logo、反馈或内容重叠。省略只作用于声明的文字槽。

## 推荐优惠券：排列与卡内构图分别决定

用户2026-10-21明确：详情推荐优惠券不限定每个页面都横向排列，也可以一行一张。适用于优惠券详情与商家详情中的推荐优惠券；参考图和既有八站产物都不是后续布局模板。

- **模块排列**决定一行放几张：可以单列连续列表，也可以在宽度足够时多列；PC与手机分别选择，不固定全部站点的列数，不强迫手机沿用PC的排法。
- **卡内构图**决定Logo、优惠、日期与动作怎样分组：图文可横向或上下组合，主券信息与领取区遵守本节上方统一区域规则；日期归入标题组。单列不等于必须左Logo右文字，多列也不等于必须做高竖卡；这两个决定不能混为同一条规则。
- 依据模块用途、实际内容宽度、信息量和本站视觉语言作决定。同站同用途按断点维持一致家族；不同站和不同用途保留自己的信息组织，不要求每个商家或每条详情路由随机换版。
- 普通推荐卡仍须固定对应家族的高度、最大宽度和文字容量；首券完整、Logo至少70×70、辅助文字至少14px、动作至少44×44、真实数量及正确全文入口继续生效。布局自由不能换来异常空带、过早省略、文字柱或漂移的按钮，也不能靠删券平衡两栏。

制作记录分别写模块列数／换列条件与卡内分组／对齐目标，并说明其对真实短长内容的适合性。审核按实际阅读、信息重点、累计间距、列表节奏和按钮归属判断；不能因采用单列、竖卡或与参考方向不同判失败，也不能仅因卡型或列数不同判通过。手机与PC都看首末卡、短长内容及换列断点两侧。

## 制作与审核的同一份记录

在 docs/site-craft.json 的 detailCraft 中逐家族记录：用途、模块、模块列数／换列条件、卡内分组、断点、宽度公式／上限、固定高度、Logo尺寸、字段取舍、文字槽行数／行高／宽度、操作位置、对齐轴、省略后的全文入口。PC和手机分别记录构图理由，不能只换颜色、背景和按钮装饰。

实际审核：

1. 先核对主／辅助区域顺序与归属、主商家至少16及主题至少8；分别计数，检查首卡、末卡及整个连续列表。
2. 同卡型、同宽度比较短标题、长标题、长商家名及日期；普通摘要卡长内容不改变规格、按钮不漂移。首券另查全文可见且没有祖先裁切。核对实际 computed style，防止旧 min-height/Grid 轨道覆盖新规格。
3. 对每个省略字段真实打开全文入口并对照冻结数据；操作不可被截断，复制实际原码。省略权限不能成为丢字段、缩字或跳过可访问性检查的理由。
4. 测PC、手机、320px与重组断点±1；查看累计间距、主侧栏实际结束点、孤立动作和空带。列高差需通过合理列数、卡型及密度解决，不拉空框、不删模块、不改变左侧三个模块归属。
5. 按本站声明的构图检查，不再把“左Logo右文字”“代码按钮同行等高”作为全部卡片的通过条件。对同批站点分别比较PC和手机，颜色去掉后仍需有真实信息组织差异。
   分别横向比较主券、推荐券、商家卡的图文分组、动作位置、列数和阅读顺序；不能只凭手机不同就放行 PC 的统一三列券行，也不能把装饰差异算成构图差异。同商家推荐隐藏店名后复查剩余空间与短标题，不能留空槽。交互元素不能用 `display:contents` 失去自己的可见焦点和实际点击区域。

旧 inspectDetail 默认检查“全文不得裁切”等历史契约。新版本使用明确的 capacityFields 参数逐项声明文字槽；未声明的字段仍按全文检查。自动几何报告不能证明全文入口、优惠语义、视觉密度或数量来源正确，仍须真实操作和独立审核。

测量参数示例：`capacityFields: [{selector: '.related .merchant', card: '.offer-row', maxLines: 1, fullTextLink: 'a.offer-link'}]`；必须替换为实际选择器，匹配非空且实际点击核验对应完整详情。首券用 `main` 或 `firstCoupon`、`firstCouponTitle` 显式覆盖，首券节点不能列入容量例外。新任务传 `logoMinimumPx:70`；仅在本站代码区和按钮并非连体构图时传 `joinedCodeAction:false`，碰撞检查仍执行。此配置不免除独立实看。

审核首券须将标题、商家名、日期及实际存在的条件说明覆盖到 mainTitle / names / dates / fullCouponFields；即使短标题暂未溢出，也禁止首券设置 line-clamp。普通容量槽仍检查全部裁切祖先，不能把中间容器遮挡当合法省略。详情双栏检查必须传 fixedPrimaryColumn:true，主推荐商家跨入侧栏即失败。

## 模块职责优先于卡片变形

用户重新对照三张参考后明确：先检查各板块的任务、占地和层级，再决定卡片外观。不能用每站强行换一种几何来代替设计。

|模块|应优先解决的问题|返工信号|
|---|---|---|
|商家身份／优惠主券|明确当前商家或当前优惠；主券完整，领取动作唯一清楚|把商家详情误当单券；长标题被Logo侧栏压成窄竖条|
|推荐优惠券|快速比较不同优惠，标题优先、期限次之、操作稳定；同商家去掉重复店名|为了差异硬做大竖卡、宽屏标题仍过早截断、重复满宽按钮抢焦点、日期装饰单独撑高|
|主栏推荐商店|扫Logo、辨店名、看有效券数，再进店；网格在信息容量和列数间取舍|低信息量商家被拉成长横条、Logo和数量重叠、店名碎成窄列、数量装饰压过品牌辨识或挤坏店名|

- 默认外框以约 1 CSS px 的中性浅线为起点，或用低强度阴影替代。它是制作目标，不是把所有站锁成同一色值、圆角或轮廓。SVG path、伪元素、内层框线也属于框线审核范围，不能只改 CSS border-color。
- 按用户要求，原有品牌边框色留给悬浮／键盘焦点／触屏按下反馈；静态状态先让内容可读。鼠标移出恢复默认浅线，边框粗细、卡片尺寸及相邻位置不跳动。主要按钮可持续用品牌色。减少动态设置保留静态颜色反馈，取消父卡和实际动画后代的运动。
- 压缩的是无效空带，不是字号、Logo 或热区：先按用途取舍字段，同店普通推荐去重复名称并移除对应轨道，再将标题、日期、操作分组。普通券只有 Logo、一行标题、日期及动作时，约 104–120px 可作为紧凑横向／镜像分组起稿预算；标题带与 Logo 分层等构图可采用更高的明确预算，但必须用实际短内容说明每层用途。数值不是全站硬模板。
- 短标题不能被一个为最长内容设置的大槽和整行按钮隔开。逐卡看字段包围盒、文字组与操作距离、内外累计间距。少字段却仍有明显连续空带，或 140–150px 高卡的大块区域没有阅读／操作用途，需重新分组，不以固定高度或跨站差异为理由放行。
- 首张完整券保持完整展示例外；不能为了普通券密度把首券裁短，也不能以首券高度为全部推荐券设置统一高槽。混合商家需要身份时为其预留真实容量，不与标题／日期重叠。辅助文字至少14px、实际Logo至少70×70、热区至少44×44继续生效。
- 密度达标不等于全部左Logo右文案。各站的构图、标题位置、动作整合和轮廓仍需分别设计；手机单独检查。主券、券列表、主商家卡、分类和侧商家按各自用途形成层级，不做一页五个同强度的装饰面板。

作者与审核者必须观察 PC、手机及320px 的默认状态和悬浮／移出状态；检查实际边框与 SVG／伪元素线条、正文层级、短长卡密度、按钮边界及变列点。记录少量代表尺寸和问题结论；不能用计划、CSS数值或单张通过截图代替八个工程逐一覆盖。该经验通过页面索引向 Harness、Codex 与 generic Agent 同时启用；已有冻结包不回写。

## 推荐券的 Logo 区域、文字轨道与真实留白（2026-10-21 用户再次返工）

普通推荐券以官方 Logo、优惠标题、截止日期和正确详情动作形成阅读单元。按站点和断点选择实际构图，不把本轮八套的具体排列固化为轮换模板。Logo 所属店铺入口及完整品牌名称通过 alt／可访问名称保留；混合商家需额外文字辨识时自然编组，不强制增加一条店名空轨道。日期前缀可按普通卡用途省去，原始日期、真实状态及首券内容保持。图标只帮助辨识真实期限或操作，不造标签填空。

- **Logo 链接、内层包装和图片分别占位。** 图片外框用 border-box 等明确盒模型；内层不因 border、padding、min-width 或继承 transform 超过外层。实际图片至少70px、动作至少44px；把外框改成72px但内图仍74px，或包装层仍按旧大槽展示，均不算修好。
- **底板和分隔必须跟随真实字段边界。** SVG rect 的 Logo 底板、票根缺口、伪元素分隔线按实际 Logo／操作组位置计算或移除；禁止保留写死95／96px等旧轨道使标题、日期进入 Logo 区域。不能用把底板涂白、截图裁掉、根部无横滚来冒充空间关系正确。
- **文字区域自身也要成立。** 测实际可见字形，不只测标题/日期盒子：检查短长标题、日期前缀、内层 span 和省略后的末行，确保字形在自身轨道内，且与 Logo 本体、外框、可见底板、分隔线和按钮没有交叠。摘要只在文字轨道省略，不能让字形溢出后进入相邻区域。
- **宽卡也要分配视觉重量。** 宽屏只有少量字段时，通过适合的列数、内容组宽度、期限组织和操作区解决空散，不能保留一条巨宽标题槽配一个孤立小按钮；也不为差异强行把所有推荐变成高竖卡。手机独立重组，固定容量与实际密度一起审核。

作者与独立审核每个工程都复查实际截图、短长内容、首末卡和客户端重绘；覆盖PC、手机、320px及变列点两侧。将本次 Castlery/RallyPerks 的「95px SVG底板越过文字起点」作为反向检查案例；不以先前内部 pass 为新版本放行依据。最终 ZIP 与站点库入口仍分别验证。

重组卡片的 `display:grid/flex!important` 必须排除 `[hidden]`，或在同一组件最终级联明确保留 `display:none`；只排除首券不够。按冻结数据或未改动原生基线核对初始折叠、All/Codes/Deals、真实零结果、展开后的可见ID顺序与数量，隐藏卡必须无渲染盒。检查器只遍历可见卡会漏掉“本应隐藏却显示”的回归，所以可见性预期须独立于最终DOM计算；不能把最终页面所有卡当作预期数量。每次客户端重绘后再复查Logo、标题、日期与按钮关系。

## 商家卡的品牌工艺、语义分类和可点击按钮（2026-10-21 最新纠正）

用户否决的是底部商家卡只换列数、其余结构和视觉完全一样；本节为后续生成与审核的长期处理方法。不是固定八种模板轮换。先沿用本站品牌语言，再决定商家身份、真实券数及进店入口的关系，比较实际 PC／同宽手机结果。

- **商家卡单独设计。** 外框工艺、Logo／名称的组合、数量字形与单位、操作入口的整合至少形成有意义的组合。可以学习目录纸页、会员通行卡、礼物卡、简洁吊牌、登机票根等处理；造型服务品牌和扫读，不能只给共同灰色数字块换位置或把所有卡加同一个彩框。店名是商家卡的文本焦点，数量辅助品牌发现，独立按钮是可选项：可以整卡通过原有真实链接进店，也可以保留融入卡片的操作提示或明确按钮，按信息密度与品牌决定，不要求每张商家卡都有箭头。取消操作后回收它的列／行，不能留空槽；整卡链接保留清楚的 hover、focus 和按下反馈。该自由不取消主券真实复制按钮。普通名称合法省略，完整身份和真实店铺入口保留。
- **密度从字段算出。** 按实际 Logo、一行店名、数量及点击区域预算高度；横向／竖向均可，短长内容不单张撑高。Logo 本体及框均至少70×70、辅助文字至少14px、真实动作至少44×44。数字与单位先在剩余宽度排好再装饰，不挤进 Logo、不裁单位；本轮既有居中选择继续核验。不能为“特色”添加没有任务的空带、假折扣或库存。
- **分类优先让人看懂，同时保留品牌选择。** 语义图标在名称左侧或上方；上下结构图标与文字同轴居中，左右结构文字左对齐；目录、标签、书签、网格可保留品牌差异，但不得省掉图标或把两字段拉成空旷长条。颜色集中在语义图形和很浅的底座，标题清楚。详情右侧不展示推荐标识及其空轨道。
图标家族、分类语义映射、来源冻结与跨站像素对照统一执行全页面公共布局底线。
- **轮廓仍像卡片／票券。** 保留克制的单对缺口、折角、切角或分隔线；默认浅细边框／轻阴影。连续高振幅波浪、密集锯齿抢过标题或让信息卡像装饰图形时收敛。旧 Paloma 连续波浪为反例，不要求为此重做其他已合适的券形。装饰层可裁切，整卡正文／焦点／动作不能用 overflow:hidden 掩盖碰撞。
- **按钮按行为、层级与品牌一起完成。** 主复制／主要购物和普通推荐导航分别确定强调程度，填色、浅底、描边或纯文字是按用途选择的材料，不把每个入口都画成厚重主按钮。主复制使用复制图标及原有真实文案／状态，导航才用箭头；图文间距、边框粗细、圆角、字体重量与光学居中形成同一组件语言。避免夸张投影、无意义多重边框或装饰拼块；图标不叠影。交互前后宽高稳定，键盘焦点清楚；精确指针 hover、手机按下与 reduced-motion 都执行既有规则。不能为了外观替换原生链接、真实复制内容或错误反馈。可参考 Radix Button 的强调变体、shadcn Button 的图文间距和 Atlassian 的操作层级，再按本站重新设计，不照搬一套外观。

审核先看八站真实像素再读造型名称：主商家区是否仍只有同一灰色数量块、分类是否名称清楚且组织方式符合品牌、精选标记是否克制有依据、可选商家动作是否正确回收空间、按钮是否一眼可知用途、卡片轮廓是否克制。逐工程／页面族／PC 与手机检查首末商家、长店名、单／双位数与实际数量重绘；核对名称、图片、数量字形和动作相交及所属边界。主商家与侧栏商家分开，侧栏继续隐藏数量且回收空轨道。几何或构图字段通过不能代替这一轮视觉判断；最终候选变化后重审受影响项，精确绑定 ZIP 和站点库入口。

按钮方法的公开参考：[Radix Button](https://www.radix-ui.com/themes/docs/components/button)、[shadcn/ui Button](https://ui.shadcn.com/docs/components/radix/button)、[Atlassian Button](https://atlassian.design/components/button/)。参考提供处理方法，不定义本系统所有站点的唯一皮肤。跨站审核必须单独比较分类组织与按钮层级；八站全用彩色图标且全部去标记，不因图标语义正确就算构图通过。

按钮与目录末尾入口仍须逐角色覆盖：复制前、成功反馈和适用错误反馈保留原文案，实测可见字形、复制图标及光学间距，不能只量按钮外框；空间不足先调整控制区的重复内边距、列比例或合理重组，不靠缩字、删图标或遮盖解决。All categories／All stores 等真实锚点同样量实际44px命中范围，不因只是文字链接漏检。公共样式涉及尺寸包含或固有尺寸时，重新覆盖每个调用页面的 Grid／Flex 父环境；普通卡盒不溢出，也要检查宿主是否缩成窄列、是否占满声明的可用宽度。

分类图标的视觉尺度与同组对齐（2026-10-21补充）：选择图标时按模块主次留出可辨识的实际图形面积，常规导航可从24–32px字形、34–44px框试排，图标主导的分类卡可从28–36px字形、44–56px框试排；这是制作预算，不是统一皮肤或商家Logo70px硬要求。检查SVG的最终width/height/min/max-size与内边距，不能只放大外框而让遗留max-height把图形压回小尺寸。精选项与普通项的图标中心线、名称文字槽保持同组对齐；标签占独立行或明确的独立位置，不能因标签把一个图标推到左边或让名称偏移。按分类宿主真实宽度换列并检查阈值两侧、长名称和手机，标签保留且不与图标/名称相交。

用户随后确认图标方案使用带颜色的语义图标：颜色集中在类别图形与很浅的图标底座，名称保留高对比中性色；可按类别搭配颜色，同时保留本站的列表、方块、书签等构图差异。新分类须包含语义图标，不允许整张卡片多色彩框；历史文字模式仅用于旧冻结包。



## 商家轴线漏检的处理

Paloma左侧末组商家券数曾因右侧箭头占列而左偏26px。此负例要求把“居中”落实到Logo、名称、券数及数量单位的实际盒／文字行；上下构图比较同一水平中轴，横排构图比较完整文字组与Logo的垂直中轴。名称自然行高、数字与单位分行或同行仍按本站风格；修复后重新检查窄屏与操作区域的可见净距，不固定一种卡型或箭头。

作者make/check与独立review都执行[商家卡轴线防回归映射](detail-standard.md#商家卡轴线与可见文字的防回归)，范围内商家卡设置requireMerchantAlignment并声明每组alignment。旧候选仅是故障证据，历史pass不能替代本轮字段与像素检查。

## 详情按钮的品牌造型与稳定动作（2026-10-22）

按钮须与本站既有字体、轮廓、颜色和券卡工艺形成明确关系，主复制／购物按钮与普通券入口共同设计。层级可由实色、浅色、细线、文字与局部工艺建立，不以统一圆角条换颜色代替品牌选择。记录主次角色、图标语义、桌面／手机形态和实际样式作用域；已有站仅改授权按钮范围，保留已确认的信息组织。商家详情仍为普通券列表，不为按钮设计恢复主券。

- **参考与原创转化分开。** 可观察真实领券页的折角、撕线和代码区，但逐项保留本站真实业务。Love Coupons 当前折起贴纸、CouponFollow 官方帮助页中的2022历史票尾示例、DontPayFull 的 Show code／Get deal 是本轮参考；历史截图标时间。不得照搬提前露出部分代码，本站揭示前仍保持 `****`。已确认八站使用杂志签条、轻折页、缎带旗尾、目录双线、登机票根、工业切角、运动斜切与礼物吊牌，属于本次品牌选择，不是以后必须轮换的八种模板。
- **动作轮廓常规可辨。** 2026-10-23现行要求：主复制／购物和普通入口使用正常矩形或圆角按钮。非交互卡壳仍可保留折角、票口和品牌工艺；不能把按钮背景裁成异形标签，pointer-events:none也不能豁免可见轮廓。真实button／a、文字、复制图标、44px热区和焦点框保持完整。无码提示作为状态文字，不做成巨大假按钮。检查最终生效伪元素与普通入口，不只检查主按钮。
- **动作语义保持原样。** 显码复制用复制图标和原有文案／成功／错误反馈，普通券入口使用导航箭头与可访问名称，无码保留真实购物行为。保留原生元素、CID/SID、真实目标、剪贴板与重绘钩子；禁止装饰覆盖操作或新增自动复制。
- **按真实空间重排。** 桌面文字入口可在既有手机图标位改为箭头，但不能把文本硬塞进44px槽。主复制仍有可见文案，必要换行时图标、文字与装饰保持净距；不靠缩小到14px以下或裁切解决。按钮内光学居中与卡片动作轴均检查。
- **验证分层记录。** 主次动作均检查 PC、手机、320px、换列断点及短长文案；普通券覆盖优惠详情与商家详情。核对伪元素可见范围、复制图标不叠影、代码掩码与原生属性未变，以及最终构建／ZIP／站点库一致。像素实看不能由几何检查代替；源码和属性不变也不能充当交互已测。用户排除交互或跨会话时尊重范围，明确记 not-run，不伪造独立审核或功能验收。
