# Coupon 生成前业务框架

2026-10-13，依据用户本轮明确要求及《Couponrite人工修改经验总结》。这份文件固定页面用途、模块职责、数据字段与行为；视觉表现继续自由。不是 Couponrite 的 DOM 或皮肤。最新用户要求优先于历史示例。

## 数据先于设计

所有后续 Coupon 新站使用 `site-data` 指定的 **新 Coupon 公共库**。先读取本次冻结 `src/site-data.mjs`、`docs/site-data.json`、原始 GET 响应及必要详情证据，再决定实际页面实例、模块选集和卡片字段。不得回退旧示例库，不从旧皮肤携带假折扣、虚构日期、成功率、人数、评分或演示说明。

市场与语言分开；按真实 ID 关联、筛选、去重。搜索、筛选、计数、静态页面与客户端重绘都从同一快照派生。优惠标题里的条件、金额或百分比是原始事实，不能删改其含义；禁止另外发明折扣字段。品牌信息、导航文案和说明页可来自真实站点配置，不能伪造邮箱、运营主体或接通不存在的服务。

## 页面清单：12 类业务/内容页 + 5 个说明页

详情页按真实记录生成多个实例；不是每个商家都发明一种页面。404 是系统状态，URL 重定向是路由设施，均不计入17种页面用途。收藏等未启用功能不自动加入。

| 页面用途 | 固定业务板块 | 主要内容类型 |
| --- | --- | --- |
| 首页 | 首页导航、原创购物 Banner、精选优惠、更多优惠、商家入口、分类入口、页脚；有真实关联内容才展示节日/省钱指南 | Campaign、券卡、商家卡、分类入口；条件性节日/文章卡 |
| 商家目录 | 紧凑页头、商家目录、页脚 | 商家卡 |
| 店铺详情 | 50px页头、Home/店铺导航、紧凑身份卡、店铺券列表、关联商家、分类/商家侧栏、页脚；仅展示未过期券，不展示过期历史 | 店铺身份、券卡、商家卡、分类入口 |
| 分类目录 | 紧凑页头、真实分类目录、页脚 | 分类入口 |
| 分类详情 | 紧凑页头、分类身份、匹配商家及各商家在当前分类的有效券数、页脚 | 商家卡；不铺券卡、文章或无关侧栏 |
| 搜索 | 一个查询框、商家优先结果、页脚；无匹配时另列替代商家，空查询保持简洁 | 商家卡；不重复铺券、无侧栏/文章/装饰筛选 |
| 全部优惠 | 紧凑页头、真实类型筛选、优惠结果、分类/商家侧栏、页脚 | 券卡、分类入口、商家入口 |
| 优惠详情 | 50px页头、主券、关联优惠、推荐商家、分类/商家侧栏、页脚 | 专用主券、券卡、商家卡；推荐商家为主栏最后购物模块 |
| 节日目录 | 紧凑页头、实际节日目录、页脚 | 节日入口；正文不放搜索框 |
| 节日详情 | 紧凑页头、节日身份、公共库真实关联券、节日切换、页脚 | 券卡、节日入口；不编造节日专享 |
| 省钱指南目录 | 紧凑页头、真实文章目录、页脚 | 文章卡 |
| 文章详情 | 紧凑页头、真实文章正文、相关文章、页脚 | 正文、文章卡 |
| About | 紧凑页头、真实服务说明、页脚 | 说明正文 |
| Contact | 紧凑页头、实际联系方式/可用联系途径、页脚 | 说明正文；未接通表单不得假成功 |
| Privacy | 紧凑页头、与实际数据处理一致的隐私说明、页脚 | 说明正文 |
| Terms | 紧凑页头、与实际服务一致的条款、页脚 | 说明正文 |
| Disclaimer | 紧凑页头、优惠来源/限制/验证边界、页脚 | 说明正文 |

节日和指南页在实际市场没有相应内容时可不启用，但必须在生成前记录数据缺口与原因；不能用虚构内容补齐。核心购物页面不得被临时营销模块替代。指南在首页最后或倒数第二，不进入优惠详情。首页区块可组合成左右栏或不同视觉分组，模块归属与职责不变，不要求照抄表格顺序。

详情页区域与容量另见[详情处理方法](../../coupon-detail-generation/references/detail-layout-methods.md)。优惠详情PC左侧固定为领取区→推荐优惠券→推荐商店，右侧推荐主题→推荐商店；主栏推荐不能跨两栏。商家详情保持自身身份与券列表。两类详情主推荐商家≥16、主题≥8。首券完整展示；其余摘要按家族与断点固定容量。

## 卡片内先决定什么

| 类型 | 必须具备 | 仅在真实且有用途时具备 | 默认不放 |
| --- | --- | --- | --- |
| 普通券卡 | 官方Logo、可辨认的优惠摘要、正确本券入口；完整源字段与全文详情保留 | 按模块用途显示商家名、截止日期/未知、Code/Deal类型、分类及有判断价值的真实优惠标签 | 描述段落、额外百分比、最低消费摘要、假验证量/热度/评分 |
| 详情主券 | Logo、商家名一次、完整标题、截止状态、有码/无码/过期类型及唯一主操作 | 明确必要的错误反馈 | 重复店铺卡、第二主操作、Conditions & source说明墙、装饰小字 |
| 商家卡 | Logo、商家名、真实有效券数、店铺入口 | 分类；分类详情使用当前分类内计数 | 日期、优惠码、重复优惠段落、假排名 |
| 分类入口 | 名称、同站一致图像/图标、分类目的页 | 真实范围内数量 | 不相关券或文章 |
| 节日入口 | 真实节日名、目的页 | 真实封面/日期、真实关联券数 | 未证实的专享优惠或紧迫感 |
| 文章卡 | 真实标题、文章入口 | 原始封面、日期、简洁原始摘要 | 整篇正文塞进卡片、虚构专家或文章 |
| Campaign | 与购物相关的原创主视觉、HTML标题、明确购物行动 | 简洁且有用的说明 | Banner内再重复页头搜索；优惠事实画进图片；无关统计/装饰眉题 |

整卡导航与内部链接职责应清楚，hover/focus和实际点击范围一致。列表有码操作进入本券掩码详情，不自动复制；仅主券显式激活后揭示并复制，刷新隐藏。无码 SHOP NOW；过期券从购物列表、推荐及主券展示中排除，失效旧链接只显示不可用提示，不展示原券内容/优惠码/领取按钮。可选侧栏变体如编辑精选/推荐顺序必须在计划里明确用途；无真实点击量不得叫热度排行榜。

文章图片字段可选指原始数据可能缺图；已有真实 `image_name` 的文章必须保留并展示封面，正文推荐项已有图片也保留实体关联。封面、卡片与正文分别按实际容器和站点风格设计，检查原图像素、响应式资源和离线导出，具体要求见[共同生成标准的文章图片部分](../../site-design/references/coupon-common-craft.md#文章图片)。不能把“缺失时可省略”解释为“有图也可以全部丢弃”。

## 固定的是业务，不是皮肤

固定数据来源、页面类型、板块归属、字段含义、关联关系、必要业务顺序、操作语义与现有尺寸/可读性底线。颜色、字体、Banner构图、卡片内构图、列数、间距、密度、分类画法、按钮造型及跨端重排自由；同一站保持一致，不同站独立设计。摘要卡可按已确认的家族文字容量省略并进入全文详情；不得缩字、截断实际优惠码/完整详情、根级隐藏溢出或照搬参考尺寸达标。

保留既有硬规则：标题/商家名16–20px，其余允许的可见文本至少14px；商家Logo实际展示区PC/手机均至少70×70，同场景等尺寸、contain、1px #EEE边框、padding0；主内容手机边距12–15px；动作≥44px；主题≥8、详情推荐真实商家≥16。数据不足先补同一公共库或说明阻塞，不复制凑数。

## 生成前必须完成

1. 公共 `workflow` 读取本框架、数据契约、业务规范及用户反馈；按目标市场冻结真实数据。
2. 写 `docs/site-structure.json`：17种页面的启用状态、路由、固定/条件模块、每种卡片的必需/可选字段、每模块真实数据来源与空数据行为，以及当前快照hash。所有普通券卡禁止字段集中列出。
3. 调用 `site_harness(action="preflight", projectId=精确ID)` 记录已验证的结构计划。工具不需要人工逐项批准；缺页面/模块、数据版本不符或乱加字段不能构建新候选。先决定框架，再开始视觉实现。
4. 在此框架内读 GitHub设计方法，组织原创构图和组件。不是把框架渲染成统一模板。作者记录长短/极端标题、少量/大量/缺图、Logo比例、实际点击和断点边界的测试选集。
5. 作者实际验证生成页面与计划是否相符；独立角色先看像素，再核对框架和H01–H08，一次汇总问题。静态计划校验只能保证计划完整和版本一致，不能证明最终页面或审美通过。

新契约只绑定之后新导入的新设计/复用/参考站项目；既有项目和历史冻结产物不会自动重写。本轮Perkport显式采用同一框架，用于首页修改和受影响回归。
