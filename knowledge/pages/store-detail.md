# 商店详情：角色、容量与跨端构图

状态：排版方法 active；全页面业务与异常状态细则仍 partial。来源为用户确认的商家页截图、普通券列表要求、长期设计质量规则及八站商店维护。截图学的是信息分组、容量和视觉层次，不冻结截图皮肤；不得把此文件解释为八个模板的统一套壳。

推荐优惠券的模块列数与卡内构图分别决定，可一行一张或合理多列，卡内可横向或上下组合；不统一全部站点的排法。具体生成与审核遵循[详情布局方法](../imported/skills/coupon-detail-generation/references/detail-layout-methods.md)中的「推荐优惠券：排列与卡内构图分别决定」。同站同用途在对应断点保持一致家族，布局自由不豁免固定普通容量、Logo下限、对齐和间距；商家列表首项与其余券采用相同规格。

右侧分类单独检查跨站分组与阅读路径，不套同一个标记／名称／箭头模板；PC券列表分别选择列数。右侧推荐商家不显示券数或“剩余数量”，同时取消其占位行，保留原数据更新钩子；主区域实际券数继续按用途展示。优惠券详情采用相同的角色取舍，具体约束见详情布局方法。

券列表、主区域商家、分类及侧栏商家均纳入动效覆盖；精确指针悬浮、移出、触屏按下、键盘焦点和减少动态实际检查。各站按既有卡片语言设计，不改变容量或入口，详见详情布局方法。

## 制作

1. 明确页面职责。PC 主栏依次是包含100×100px Logo、完整商家名和真实优惠券数量的商家卡（总高≤200px）、该店优惠券、推荐商店；按2026-10-22最新纠正，各站风格自由，商家卡下紧接券列表（已有筛选可保留），不能退化成纯文字标题；面包屑、券内身份或隐藏标题不能替代商家名与数量；辅栏依次是主题／分类、其他商店。原有事实说明和官方链接可紧凑保留在合适位置。手机先主栏再辅栏，按实际容量重组。店铺身份不是领券面板；店铺券链接仍前往它自己的优惠券详情。
2. 同站同用途复用已认可的语言，分别设计比较券、商店发现和分类导航。固定“用途×断点”的宽高上限、文字槽和动作位置；不同站及不同用途应在阅读路径、轮廓、信息分组中有实质差异。齿口、折角、票根、切角、封签等由本站选择，不能只换颜色，也不要求每个角色都带相同装饰。
3. 商家卡后全部优惠券使用普通列表家族，首张不独立放大或跨满整行；筛选、展开或重绘后也不提升首券。保留原始CID、完整源数据、顺序和真实详情入口；各券按普通摘要的既定容量展示。标题16–20px、辅助文字至少14px，不留无效空轨道。优惠券详情主券完整要求仍保留。
4. 商家卡 Logo 实际图片为100×100 CSS px；普通券与推荐商家 Logo 实际图片展示区至少70×70 CSS px，通常72或80px即可；图框尺寸不能代替图片尺寸。不扩张到素材锐度任务。真实动作触控至少44×44px；店铺 Code 与 Deal 的标题和动作均进入该卡自己的优惠详情，外部领取／SHOP NOW 留在优惠详情。移植旧外跳按钮时还要清理原 target，并调整标签以符合导航行为。纯图标动作需有完整可访问名称；隐藏的按钮文字和 aria-hidden 的 SVG 不能充当名称。不能把导航写成已经复制。
5. 用实际容量选择列数：可用宽度必须容纳 Logo、标题／商店名、真实数量、动作、内边距和间隙。数量与名称是独立节点，不能把含实时数量的外层容器当作名称后再覆盖其 textContent。保留原生更新钩子、ID、顺序、链接和筛选控件；不能为左右等高删券、删商店或虚增内容。所有普通推荐固定单行容量；优惠详情主券全文例外不适用商店列表。
6. 卡间以8–12px、标题到首卡约8px、模块间约20–24px为紧凑制作起点；按用途调整，最后测真实边到边累计距离，不能只读 gap。PC 长列表可在实际卡片容量允许时用多列，手机单列或较少列；不能在窄屏硬塞 PC 的商店数量列。背景以白色或很浅的本站颜色为主，文字和动作必须有足够对比。
7. 手机 header 除品牌外采用 icon 或小型组件；搜索仍使用真实原表单，展开、输入、提交、Esc 和焦点都可用。隐藏的原生分页／筛选节点必须继续隐藏，grid/flex 不得覆盖 `[hidden]`。
8. 布局标记使用独立新属性，不能将既有 `data-side-merchant` 等业务 ID 改为空值。按原冻结数据逐个比较属性值、链接、顺序和实时数量节点；href 正确不代表 ID 钩子保留。手机主栏已展示的商家不在侧栏重复展示：按真实 ID 隐藏重复侧栏项，保留主栏数量、手机独有商家的顺序／链接／数量与 PC 原侧栏全集。

## 审核与交付

- 先冻结真实数据与旧构建。每个工程单独核对代表商家、长内容商家、首券、短长普通券、末券、完整推荐商店和侧栏；项目数不能由抽查一套推断。
- 实看1440、1024、768、393／375、320及发生重组断点的两侧。检查卡内每个角色和真实文字边界，不只检查页面横向滚动。合法省略必须落在承载文字的内层；所有普通券标题单行省略，首项与后续一致；不得互相覆盖或越出自身轨道。
- 原生存在的 All/Codes/Deals、零结果、重置、展开、加载更多和刷新都实际点击；比较真实可见 ID 顺序和计数。真实 Code/Deal 的首券、普通券及筛选后首券都要点击箭头核对自身 CID，不能用标题跳转通过代替箭头通过。检查可访问树中纯图标动作的名称，逐值核对业务 ID，并统计手机主／侧栏重复 ID。操作推荐商家、分类与搜索，核对落点。真实样本不存在则记 N/A，不造数据。不增加虚构的“剩余库存”“热度”；数字是实际优惠数量，序号是导航顺序，编辑推荐需有明确含义。
- 主侧栏结束点差异较大时做完整 PC 视觉复核，以真实内容密度和模块关系判断。不得用空框、占位高度或复制内容凑齐；未改业务的长清单差异必须如实记录，不能伪称全页平衡已通过。
